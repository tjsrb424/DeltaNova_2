# 행성 대시보드 실제 플레이 검수

2026-10-14. 상태: 완료 알림 보완·검수 준비 완료. 162개 테스트·빌드·API/정적 자산 제공의 헤드리스 검증이 통과했다. 아래 항목은 사용자가 직접 확인할 검수 순서이며 실제 화면·입력·음성·재미 검수가 끝났다는 뜻은 아니다.

## 실행

main에 반영된 버전에서 다음 명령을 직접 실행한다. 이전 개발 서버가 실행 중이면 해당 터미널에서 Ctrl+C로 종료한 뒤 다시 실행한다.

```powershell
cd D:\kim_dev\DeltaNova
npm run dev
```

서버 준비 메시지 뒤 [테스트 화면](http://127.0.0.1:5173)을 직접 연다. 웹과 API가 함께 실행되어야 하며 `preview`/`dev:solo` 대신 위 명령을 사용한다. 브라우저는 자동으로 열리지 않는다.

개발 참가자를 고르고 **참가자로 연결**을 누른다. 기존 참가자의 자원·함선·작전은 저장 상태를 따른다. 처음 사용하는 참가자의 기준은 합금120·결정80·연료80, 함선9척이다. 각 확인은 시작 전 수치와 비교한다. 검수를 위해 저장 DB를 삭제하거나 초기화할 필요는 없다.

## 첫 순환: 약 10~15분

| 순서 | 조작 | 확인할 결과 |
|---|---|---|
| 1 | 행성 화면에서 생산 시설·조선소·방어 거점을 차례로 선택 | 선택 표시와 오른쪽 제목/비용이 같은 대상을 가리킨다. 현지 행성명·자원·전력·공간을 읽을 수 있다. 실제 본성1개만 표시한다. |
| 2 | 조선소에서 케스트럴 수량1과 비용을 확인하고 건조 | 합금40·결정20·연료10을 한 번 사용하고 약40초의 작업이 시작된다. 예정량은 가용 함대로 포함되지 않는다. 생산 증가는 별도다. |
| 3 | 건조를 기다리며 수량 입력에 포커스를 두거나 다른 메뉴로 이동했다 돌아오기 | 완료 후 최대 약3초의 조회 간격 안에 재고가1척 늘고 진행 목록에서 빠진다. 행성명과 완료 내용의 알림이 표시되며 입력 포커스를 빼앗지 않는다. |
| 4 | 상태 새로고침을 반복하고 동맹/행성 메뉴를 왕복 | 이미 확인한 완료를 반복해서 알리지 않으며 함선을 다시 지급하지 않는다. 첫 연결의 과거 보고서도 완료 알림으로 읽지 않는다. 같은 종류의 새 작업이 다시 끝나면 별도로 알린다. |
| 5 | 개인 작전에서 **고요한 잔해지대**, 추천 편성, 지원을 확인 | 추천 편성의 케스트럴 한 척을 새로 건조한 함선으로 교체한다. 지휘/함선 제한·출격 연료·가용/정비 상태가 일치한다. 출격하면 해당 함선이 출격 중으로 바뀐다. |
| 6 | 교전 후 귀환을 선택하고 함대 화면에서 손상 함선을 정비 | 화물·손상이 출발 기지에 반영된다. 손상 함선의 출격 제한과 합금 정비 비용을 확인하고 정비 후 다시 가용 상태인지 확인한다. 자원이 부족하면 화면 사유를 확인하고 생산을 기다린다. |
| 7 | 동맹에서 정찰대 예약, 새 함선 포함 편성, 역할 수행 | 대시보드에서 완료를 확인한 새 함선이 별도 개인 명령 없이 공동 선택 목록에 보인다. 기존 손상 함선은 정비하고, 수행 후 보고서·연료·손상·공헌이 한 번 반영되는지 확인한다. 이미 예약/완료된 역할은 화면 상태를 따른다. |
| 8 | 생산 시설 증설 또는 산업 연구를 시작하고 완료 확인 | 시작 비용·시간·출처와 진행 목록이 일치한다. 완료 후 수준/생산률/보고서와 완료 알림이 갱신된다. 같은 조회에 여러 작업이 끝나면 각 출처와 내용을 함께 알린다. |

## 입력과 표시

- 새 조선을 시작한 직후, 완료 전에 취소를 눌러 표시된 80% 반환을 확인하고 취소 확정을 누른다. 원 지불 기지에만 반환된다. 이미 완료됐거나 반환 저장 공간이 부족한 경우 화면 사유를 확인한다.
- 건조 수량0/21 또는 자원이 부족한 수량을 입력하면 실행이 막히고 이유가 보이는지 확인한다.
- Tab/Shift+Tab으로 메뉴·시설·입력·버튼에 접근하고 Enter/Space로 조작한다. 포커스가 눈에 보이고 선택 상태를 색만으로 설명하지 않는지 확인한다.
- 스크린리더를 사용한다면 새 완료 내용을 진행 중 음성을 끊지 않고 읽는지, 같은 완료를 반복해 읽지 않는지 확인한다. 자동 검증은 DOM live region과 중복 갱신 방지만 확인하며 실제 음성 동작은 이 검수 항목이다.
- PC 브라우저 폭을 좁혀 HUD → 행성/시설 → 행동/진행 정보를 읽고 조작할 수 있는지 확인한다. 글자·수치·선택·그림의 겹침과 잘림을 기록한다. 이는 좁은 화면 검수이며 현재 루프백 서버의 휴대폰 원격 접속을 뜻하지 않는다.
- 동작 줄이기 설정을 사용하는 경우 과도한 전환 없이 동일한 정보와 조작을 제공하는지 확인한다.

## 저장과 복구

진행 중인 작업을 둔 채 페이지를 새로고침한다. 비용 재청구나 재고 복제가 없이 남은 작업 또는 완료 결과를 유지해야 한다. 서버를 정상 종료하고 같은 명령으로 다시 실행해 같은 참가자로 연결한 뒤 자산이 유지되는지 확인한다.

통신 문제가 생겨 **미확정 명령** 안내가 나왔다면 원래 화면에서 **같은 명령 재전송**으로 확인한다. 세션이 만료되면 같은 참가자로 연결한 뒤 재전송한다. 확인 전 다른 화면의 새 자산 명령과 참가자 변경이 제한되는지 확인한다.
