# Codex 실행 로드맵 — Audit → Bible → Slice → Validate → Rollout

## 단계와 의도

| 단계 | 실행 | 산출물 | 완료 게이트 |
|---|---|---|---|
| P0 | 저장소 실사/기능 지도/현재 화면 확인 | `UI_AUDIT.md`, 구조 지도, 리스크 목록 | 실제 근거가 있는 진단 |
| P1 | 디자인 토큰/IA/모션 규칙 검토·충돌 수정 | `DESIGN_BIBLE_REVISED.md`, 변경 제안 | 모든 규칙의 충돌 없음 |
| P2 | 분리된 행성 메인 시연물 | Idle/Threat/Complete 3상태 + 스크린샷 | G2 사용성 비교 가능 |
| P3 | 사용자 평가 반영·품질 측정 | 점수표, A/B 개선 내역, 과제 테스트 | 9.5/10 목표 & 치명 오류 0 |
| P4 | feature flag 뒤 실제 컴포넌트 이관 | 실제 데이터 연결, 회귀 테스트 | 승인 후만 통합 |
| P5 | 나머지 주요 화면 확대 | 건설/연구/함대/은하/동맹/랭킹 | 화면별 승인·회귀 |

## 첫 Codex 실행이 반드시 수행할 내용(P0~P2)

1. `git status`, UI 경로, 패키지와 빌드·테스트 스크립트, AGENTS.md를 확인.
2. 모든 주요 화면/컴포넌트와 데이터를 공급하는 레이어 목록 생성.
3. 현재 실행 화면 또는 기존 스크린샷이 있으면 1920×1080/390×844의 핵심 UX 문제를 기록; 실행 불가능하면 **왜 불가능한지** 명확히 남김.
4. `정보 과다 / 계층 혼란 / 디자인 편차 / 행동 발견성 / 상태 처리 / 성능`으로 문제를 분류하고 근거와 심각도 제공.
5. 현재 UI와 이 패키지 사이의 충돌을 식별하고 대응안을 제안. 확정되지 않은 사실을 디자인 상수로 쓰지 않음.
6. 바이블 후보를 현재 코드베이스에 맞춘 제안 문서로 작성.
7. 3상태 시연 화면을 기존 앱과 **분리된 sandbox/demo/feature flag 경로**에 제작. 앱을 변경하지 않는 독립 HTML도 가능.
8. 디자인 변경 전/후의 비교 샷 또는 재현 가이드를 제공.
9. 린트/타입체크/빌드/기존 테스트 가능한 항목을 실행, 통과·실패를 실제 결과로 보고.
10. 다음 P3 디자인 평가와 사용성 검증이 가능하도록 5개 과제 테스트 제공.

## P2 시연물 요구사항

- 단일 메인 레이아웃에서 **Idle / Incoming Threat / Action Completed**가 명확히 변해야 함.
- 데스크톱과 모바일에서 동일 상태를 각각 검토할 수 있어야 함.
- 사용자가 탭·메뉴·주요 행동을 클릭할 수 있는 실제 상호작용 포함.
- 샘플 데이터는 `DEMO`로 표시; 서버 로직/함대 이동/경제 변경 코드 사용하지 않음.
- 장식이 아닌 '상황 인지 → 행동 선택 → 결과'의 피드백을 보여줘야 함.

## 기존 코드와 연결하는 경우의 전략(P4 이후)

- 토큰을 공통 CSS 변수로 마이그레이션하되 기존 정의를 조사하고 중복 선언 방지.
- 공통 Shell을 우선, 그 다음 자원·버튼·상태 배지, 그 다음 패널과 행성 비주얼.
- API는 기존 query/state layer를 그대로 사용. UI 전용 view model 변환이 필요하면 독립 계층에 격리.
- UI 버전 전환에는 rollback/feature flag 가능성을 확보.
- 같은 페이지에서 레거시와 신규 UI가 잠깐 공존할 수 있으나 시맨틱 색 토큰 혼합 금지.
- 스타일 값의 상수 하드코딩이 늘어나면 토큰 설계로 재정리.

## 완료 리포트 형식

`REPORT_TEMPLATE.md` 양식을 따른다. 반드시 다음을 담는다:
- 실제 확인한 사실 / 미확인 / 디자인 제안.
- 바뀐 파일과 범위, 미변경한 게임 로직 확인.
- Before/After 스크린샷이나 재현 경로.
- 사용자 테스트 결과·해상도별 결과·접근성·모션·성능 검사.
- 점수표와 개선 우선순위, 남은 위험, 승인 필요 결정.

## 리스크 관리

- 프레임워크 미확인: 설치부터 진행하지 않음.
- 아트 미확정: CSS/그래픽 시연만 먼저; 3D 미도입.
- 개발 도중 버그 발견: UI와 무관한 게임 로직 문제는 별도 보고, 무단 수정하지 않음.
- 데이터 없음: 샘플 데이터와 실제 데이터를 분명히 분리.
- 사용자가 이전 화면으로 돌리고 싶을 때: 백업/feature flag/명시적 변경 목록이 있어야 함.
