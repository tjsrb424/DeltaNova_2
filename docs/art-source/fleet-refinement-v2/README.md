# 함대 그래픽 V2 · 원본과 검토

2026-10-16 · 독립 데모 · 기존V1 및 생성 중간 후보 보존

기존8함종을 원본·실제120px 카드에서 다시 검토했다. 이전 화면 종합 평가는 개별 함선 비트맵의 품질 인증이 아니었다. 이번 검토에서는 정찰함9.60, 격납고9.60을 제외한7종이8.80~9.30으로 보완 대상이었다. 수리/회수의 복잡한 관절, 교란의 가는 안테나 군집, 회수/항모의 좁은 셀 여백을 수정 대상으로 삼았다.

## 후보와 채택

1. `roster-clean-candidate.png`: imagegen 편집1차. 큰 패널·관절·신호 패널로 잔선을 정리했다. 여백이 부족해 **미채택**.
2. `roster-padded-candidate.png`: 같은 후보를 imagegen으로 다시 편집해 각 셀 안에 축소/정렬. 실제 크기·투명 경계·구조를 재검토했다.
3. `roster-padded-candidate.webp`:1280×640 q84 검토용 중간 인코딩. [comparison-sheet.png](./comparison-sheet.png)는 V1/120px, 후보/120px, 후보/160px의 QA용 비교 시트다.
4. `roster-runtime-candidate.webp`: 최종1600×800 q86/alpha100. `public/uiux-demo/art/fleet-roster-v2.webp`와 같은 바이트다. 각400px 셀을160px 프레임으로 표시한다.2.5배 소스 해상도이며 DPR3을 실제 기기 선명도 보장으로 표현하지 않는다.

모든 조작은 원본과 중간 후보를 보존했다. sharp는 크기 조정/인코딩과 검토 시트/경계 측정에만 사용했다. 함체 정리와 배치 편집은 내장 imagegen을 사용했다. [프롬프트 원문](./prompts.json), [파일 해시](./manifest.json).

## 점수

주관적 내부 검토이며 자동 AI 노이즈 판별·객관적 인증·사용자 승인과 다르다. 구조3/청결2/스타일2/표시 크기2/알파·비용1의10점이며9.5점 **초과**가 채택 조건이다. 실제 카드에160px 표현을 유지해야 다음 점수가 유효하다.

## 실제 적용 검증

카드의 이미지 프레임을160px로 유지하고 좁은 열의 최소 폭을120px로 조정했다.1920/1440/1152/1024/839/768/760/390/361/360/320px에서 이미지의 실제 불투명 픽셀 경계를 부모 영역과 대조했다.361px에서 발견한 약2px 잘림은 열 너비를 보완해 해결했다. 단순히 img/span 박스만 검사해 투명 여백을 잘림으로 오인하지 않았다.

[실제 카드·접근성·모바일 검증](../../qa/2026-10-16-mobile-a11y-loading/README.md)을 확인한다. 픽토그램/게임 수치/함선 역할은 원래 모델을 사용하며 아트에서 추정해 바꾸지 않는다.
