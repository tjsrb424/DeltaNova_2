# 장기 로드맵 — 랭킹·동맹 정치·서버 생태계

## 판정: 설계는 유지, 즉시 구현은 보류

델타노바의 성장과 경쟁 재미를 확장하려면 랭킹 점수 설계를 게임 기획과 함께 진행해야 한다. 이번 UI 리뉴얼은 공통 토큰·탭 구조·정보 표시 컴포넌트 준비까지. **랭킹의 실제 집계 API와 운영 기능을 UI 개편 도중 임의 추가하지 않는다.**

## 권장 랭킹 분류

- **종합:** 경제 투자·건물·연구·전력 관련 자산을 조합해 추적하는 장기 성장 지표.
- **전투:** 공격·방어 관련 기여를 구별하고 허위 전투/자작 승부 악용 방지.
- **성장:** 기간 내 순증분, 신규/후발 유저에게도 경쟁 기회 제공.
- **약탈:** 실질 획득·손실 등 맥락을 고려하며 다중 계정 반복 약탈 악용 차단.
- **방어:** 피해 억제, 대응 성공 등 방어형에게 명예 목표 제공.
- 향후 **동맹/서버 시즌**은 집계가 검증된 뒤 연동.

## 점수 설계 원칙

1. 총점 하나로 경제·PvP 모두를 설명하려 하지 않는다.
2. 저장된 자산과 누적 소비를 중복 계산하지 않는 원장이 필요하다.
3. 실제 도입 전 점수 공식 시뮬레이션과 레벨별·과금 그룹별 분포 확인.
4. 2차 계정, 반복 약탈, 의도적 병력 손실로 점수 부풀리기 방지.
5. 순위 변동은 집계 지연/차트를 포함한 사용자 기대 관리 대상.
6. 시즌/서버 구분과 점수 갱신 시점·동점 정책을 UX에 명시.

## UI 공통 구성

- 상단 `종합/전투/성장/약탈/방어` 탭(서버 기능 도입 이후 활성화).
- `이번 시즌/전체` 선택 및 집계 기준일, 랭크 변동 기호/설명.
- 리스트: 순위, 이름/동맹, 점수, 최근 변동, 상세 진입.
- 뱃지 색상은 의미를 갖고 배경 글로우를 남발하지 않는다.
- 상위 랭커의 존재감보다 순위 탐색, 내 위치, 추적 대상 검색을 우선.

## 구현 전 결정할 것

- 각 순위의 산식, 재화 인플레이션 처리, 기간성 반영, PvP 보정.
- 시즌 종료와 점수 확정 방식, 동맹 합산 기여 규칙, 어뷰징 대응.
- 스냅샷 주기, API 응답과 캐시 정책, 익명화·신고·차단 가능성.

## 이렇게 테스트하세요

- 모의 데이터 분포를 생성해 초기/중반/후반 유저의 순위가 왜곡되지 않는지 확인.
- 전투/약탈/방어형 플레이의 행동 유인이 과도하게 편중되지 않는지 확인.
- 시즌 갱신/데이터 지연/비공개 대상/동점 처리가 명확한지 검증.
