## 행성 아트와 상태 연결

내장 이미지 생성 도구로 자연 표면만 생성했다. 사용 파일은 [nova-natural-v2.webp](../../public/uiux-demo/art/nova-natural-v2.webp),768×768 투명 WebP,190,454bytes다. 원본과 SHA256, 실제 생성 프롬프트는 [아트 기록](./ART_PROVENANCE.md)에 보존했다. 별도 라이브러리를 설치하지 않았다.

도시광은 개별 시설 수준, 궤도 조선소의 표시·크기·확장부는 `facilities.shipyard`에 연결했다. 자연 아트와 시설 레이어가 분리되어 시설 스냅샷 변경이 실제 DOM 시각 레이어를 바꾼다. 완료 연출만으로 시설이나 자원이 증가하지 않는다. 이번 데이터는 명시적 fixture이며 운영 서버 연동 결과로 제시하지 않는다. 베스퍼는 현재 동일 자연 지형의 색조 변형이다.

WebP 로딩 실패 시 보존된 절차 구체로 복귀한다.512px Canvas·행성2개 캐시·비동기 요청 구별·모션 감소를 유지한다. 제어된 이미지 지연 중에도 위협 입력이 동작했다.

## 성능 표본과 해석 범위

최종 dist의 Chrome CPU4배 감속, WebP 요청을 일시 보류한 단일 실행에서:

- 브라우저 click 이벤트부터 double requestAnimationFrame까지의 **표시 반응 proxy58.4ms**.
- 자동화 도구의 locator/통신을 포함한 왕복138.2ms는 별도로 기록.
- 관측 long task137/57/66ms;250ms 이상0건.
- 실제 수신한 WebP body190,454bytes.

doubleRAF는 물리 입력 지연·이벤트 대기·compositor의 실제 표시 완료를 포함한 INP가 아니다. `planetRenderMs`415/166.2ms는 이미지 게이트 대기를 포함하는 전체 완료 경과 시간이며 CPU 연산 비용으로 해석하지 않는다. 초기에는 자동화 왕복 전체를250ms 기준과 비교해 실패가 발생했으므로, 브라우저 내부 측정과 도구 지연을 분리했다. 최종 검사는 동일250ms 브라우저 proxy/long task 기준으로 통과했다.

성능 표본은 실기 FPS/GPU/배터리·저사양 보증이나 운영 앱과의 통제된 A/B 결과가 아니다. 관측값 전체는 `after/quality.json`에 있다.

## 보존 범위와 다음 작업

이 보고서 작성 당시 브랜치 `codex/uiux-refoundation`, HEAD `6724252b4b1796d051c108255c2b76334784630f`, 기존 tracked 파일 diff0이었다. 당시 UI/문서/QA 산출물은 untracked였고 commit/push/배포하지 않았다. 이후 사용자 요청에 따른 게시·재개 상태는 [HANDOFF](./HANDOFF.md)와 원격 브랜치에서 확인한다. 운영 React/CSS, 경제·전투·이동·정찰·연구·건설 수식, API/DB/저장은 변경하지 않았다. 운영 bundle 이름/크기 또한 기존 CSS116.54kB/JS354.59kB와 같다.

1. 실제 iOS Safari/Android Chrome에서 세로·가로·글자 확대·노치/키보드·스크롤을 점검하고, 발견한 기기별 결함만 독립 데모에서 수정한다.
2. NVDA/VoiceOver로 자원 설명·위협1회 알림·중첩 상세·닫기 복귀를 검수하고 실제 사용자 A~E 과제의 인지 시간과 오해를 기록한다.
3. 데모 디자인과 검수 결과 승인 후에만 실제 snapshot adapter/공통 Shell 이관 범위를 별도 제안한다. 현재 전체 서비스 교체는 시작하지 않는다.

## 이렇게 테스트하세요

1. [독립 데모](http://127.0.0.1:5173/uiux-demo/index.html)를 연다. 반드시 `index.html`까지 입력한다. 서버가 꺼졌으면 `npm run dev:solo -- --port 5180 --strictPort` 실행 후5180의 같은 경로로 접속한다.
