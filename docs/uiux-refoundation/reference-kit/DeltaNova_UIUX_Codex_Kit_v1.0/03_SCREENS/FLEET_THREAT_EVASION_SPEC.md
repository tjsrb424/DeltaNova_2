# 적 함대 접근 / 함대 회피 UX 명세

## 판정: 수정 — 회피는 긴급한 의사결정이지 자동 연출이 아니다

이 문서는 **현재 게임에 있는 실제 함대 시스템을 확인하기 전의 UX 설계**다. 회피의 목적지·속도·시간·취소/귀환 규칙을 새로 정의하지 않는다. 기존 게임 로직 위에 올바른 판단과 안전한 명령 검토를 얹는다.

## 상태 흐름

```text
NORMAL
  └─ 서버가 적 접근 이벤트 전달 → THREAT_NOTICE
THREAT_NOTICE
  ├─ [상세 보기] → THREAT_DETAIL
  ├─ [무시/닫기] → NON_BLOCKING_BANNER (위협 상태 지속 시 표시)
  └─ 이벤트 종료/철회 → NORMAL
THREAT_DETAIL
  ├─ [방어 현황] → DEFENSE_VIEW
  ├─ [함대 회피 계획] → EVASION_REVIEW
  └─ [닫기] → THREAT_NOTICE
EVASION_REVIEW
  ├─ 입력/제약 미충족 → DISABLED_WITH_REASON
  ├─ [검토/확정] → SERVER_PENDING → ACK_SUCCESS | ACK_FAILURE
  ├─ 타임아웃 → UNKNOWN_RESULT (무작정 재전송 금지; 서버 조회)
  └─ [취소] → THREAT_DETAIL
```

## 화면에 표시할 정보의 우선순위

1. 어떤 **행성**에 위협이 오는가?
2. 어떤 **이벤트**인가? 실제로 확인된 공격/정찰 등 이벤트 유형만 표시.
3. 실제 서버 기준 예상 도착 시각 및 남은 시간(동기화 불확실하면 시각만).
4. 회피를 검토해야 할 대상 **함대/자원**이 무엇인지 (기능이 있으면 표시).
5. 어떤 선택지가 유효한가? 상세/방어 확인/회피 계획/대응 없이 닫기.
6. 회피 명령 전에 반드시 확인해야 할 함대·목적지·소요 시간·비용·보호 불확실성.

## 경보 레이어

- **Tier 0 Critical:** 실제 위험 이벤트가 새로 발생했을 때 표시, 눈에 띄는 색+명확한 텍스트.
- 과도한 Modal takeover 금지. 다만 게임 설계상 강제 경고가 정말 필요한 경우 사용자 안전·운영 기준 검토 후 결정.
- 반복적으로 동일 이벤트에 새 토스트 생성 금지. eventId 단위 업데이트 우선.
- 접속 중/탭 이동/재접속/서버 시간이 바뀌는 상황을 고려해야 함.
- 랭킹/외교 화면에서 이벤트를 받더라도 현재 행성/컨텍스트가 무엇인지 혼동하지 않게 함.

## 함대 회피 검토 패널의 권장 필드

| 필드 | 동작 |
|---|---|
| 현재 행성 | 고정 표기, 상황에 따라 변경 제한 |
| 대상 함대 | 실제 게임에서 유효한 함대만 선택 |
| 회피 목적지 | 가능한 타깃과 금지 사유 실제 규칙 반영 |
| 예상 소요 시간 | 서버 기반 계산 또는 명시적 계산 기준 안내 |
| 자원 탑재 | 게임이 지원할 때에만, 가능 범위 표시 |
| 위험 요소 | 회피가 무조건 성공한다고 보장하지 않음 |
| 실행 버튼 | `함대 이동 명령 확정` 등 실제 행동을 설명 |

## 긴급 UX 실패 방지

- 남은 시간이 0에 가까워질 때 버튼만 깜빡이지 않고 실제 가능 여부 갱신.
- 발진 버튼 중복 클릭 방지 + 서버 ACK 기반 최종 결과 표기.
- 이벤트 취소/전투 도착 시 UI에 오래된 경보 유지 금지.
- 악의적인 클라이언트 조작으로 명령이 유효해지지 않도록 기존 서버 권한 검증 유지.
- 사용자 명령이 실패했다면 자원/함대 수치가 부분 반영된 것처럼 보이지 않아야 함.
- 회피 도중 적 공격을 피할 수 있는지 여부는 실제 게임 수식 확인 전 추정 금지.
- 무과금 유저의 중요한 경보 인지/대응 경로를 과금 기능에 종속시키지 않는다.

## 상태별 카피 예시 (문구는 게임 용어에 맞게 현지화)

- 경고: `적 함대 접근 중 · [행성명]`.
- 상세 CTA: `공격 정보 보기`.
- 계획 CTA: `함대 회피 계획`.
- 검토 단계: `이 함대의 이동 명령을 검토합니다.`.
- 서버 확인 전: `명령 접수 확인 중`.
- 실제 응답 성공 후: `함대 이동 명령이 접수되었습니다.`.
- 실패: `명령을 처리하지 못했습니다. 함대 상태를 새로고침한 뒤 다시 확인하세요.`.

## 이렇게 테스트하세요

1. 같은 eventId가 여러 번 갱신되어도 배너가 중복되지 않는다.
2. 경보 도착 전/중/후, 서버와 클라이언트 시각이 차이가 나도 시간 정보가 오해되지 않는다.
3. 회피 패널을 열었다가 닫아도 이전 선택 행성과 열려 있던 상세 맥락이 유지된다.
4. 대상 함대가 사라지거나 이동 중이 되면 검토에서 유효성 검사를 실패한다.
5. 서버 명령에 타임아웃이 발생해도 `성공`으로 표시하지 않는다.
6. 모바일에서 긴급 CTA를 다른 탭 UI가 가리지 않는다.
