## 기존 함대 그래픽 재평가

구조3/청결2/일관성2/표시 크기2/알파·비용1. 주관적 내부10점 평가이며 **9.5점 초과**가 채택 조건이다. 원본과 실제120/160px 표시, 데스크톱/모바일 카드, alpha 경계를 확인했다. 첫 정리 후보는 안전 여백이 부족해 반려하고 배치를 편집했다. 전체 UI의 이전9.50점으로 기존 함선8종을 일괄 승인하지 않았다.

V2의9.60~9.70은 **160px 이미지 프레임의 카드**에 대한 판단이다. 선체 연결·무장/집게 구분·안테나 군집·금속 면·선명한 실루엣을 살피고, 확인한 크기에서 떠 있는 파편/의미 없는 미세 잔선/검은 배경 테두리를 발견하지 않았다. 자동 AI 노이즈 탐지나 사용자 승인은 아니다. 모바일 접근성/성능의 자동 통과율을 임의의 종합 UX 점수로 변환하지 않는다. 실기기까지 포함한 전체9.5점 달성을 확정하지 않는다.

400px 셀의 불투명(alpha>32) 선체 여백은 최소53px(13.25%), 외곽4px의 유효 픽셀0. 런타임 WebP는239,316→148,454bytes,90,862bytes(38.0%) 감소했다. 보존한 V1 파일은 저장소/빌드에 남으므로 전체 배포 파일 합계 감소라는 뜻은 아니다. [함종별 사유·원본·프롬프트·반려·해시](../art-source/fleet-refinement-v2/README.md).

## 로딩 성능

390×844/DPR3, cache off, 다운로드1.6Mbps·업로드750kbps·설정 latency150ms·CPU4배 slowdown의 **사용자 정의 headless 조건**이다.4화면×전후3회, 순서를 교차한24 cold context 표본을 전부 보존했다. 기본 Playwright/Chrome runtime을 사용했고 패키지를 추가하지 않았다.

아래는 중앙값이다. 시간ms, 본문bytes. `ready`는 DOM 초기화 뒤 MutationObserver 시각이며 사용자의 입력 반응을 뜻하지 않는다. `shift 합`은 관측한 초기 layout-shift의 단순 합으로 공식 session-window CLS/Web Vitals 판정과 다르다. LCP는 명시적 입력 전 마지막 관측값, 본문 합은 decodedBodySize로 압축 전송량이 아니다.

| 화면 | ready 전→후 | load 전→후 | shift 합 전→후 | 리소스 본문 전→후 |
|---|---:|---:|---:|---:|
| 행성 |5591.1→4921.0 |6079.4→5319.5 |0.240115→0 |866810→868986 |
| 건설 |4889.7→3172.3 |5906.0→4217.1 |0.054165→0 |1058954→590764 |
| 연구 |5262.1→3062.0 |7722.5→4456.3 |0.054165→0 |1117808→649618 |
| 명령 |5201.1→6355.8 |7178.2→6358.7 |0.054165→0 |1259110→700058 |

직접 진입한 건설/연구는468,190bytes, 명령은559,052bytes 줄었다. 홈은 JS/CSS 보완으로2,176bytes 늘었다. 최종 개선 후12개 표본 모두 초기 shift 합0이었다. 기본 텍스처를 홈에 남겨 몰입감을 보존했다.

**명령 ready 중앙값은1154.7ms 악화됐고 입력 doubleRAF p95도59.5→157.7ms로 악화됐다.** 입력 중앙값은29.55→21.45ms였지만, 이를 실제 INP/터치 성능 개선으로 해석하지 않는다. 각 전후18회 합성 입력이며6회/로드이다. 명령 ready 범위는 전5133.2~5618.0 / 후2921.7~14249.1ms, 홈 후 ready 최대22199.2ms, 연구 전 최대30581.5ms였다. 일부 표본의 긴 task와 큰 변동이 함께 관측됐다. 공유 호스트 영향과 코드/렌더 비용을 분리하지 못했으므로 모든 화면의 속도 개선이나 전체 성능9.5점 달성을 주장하지 않는다. 이상치를 제거하거나 좋은 재실행으로 대체하지 않았다. [전체 표본](../qa/2026-10-16-mobile-a11y-loading/performance.json), [최소/최대·정의](../qa/2026-10-16-mobile-a11y-loading/performance-analysis.json).

## 남은 검수

실제 iOS/Android의 키보드·안전 영역·터치, VoiceOver/TalkBack 발화, 배터리/GPU와 실제 INP는 미검수다. 수동 캡처 검토와 Chrome AX tree/키보드 테스트는 이 항목들을 대체하지 않는다. 다음 성능 검수는 통제한 물리 기기에서 명령 진입/편성 입력의 지연을 우선 계측한다. 사용자 승인 전 데이터 adapter나 운영 UI 이관을 진행하지 않는다.
