# 델타 노바 다중 행성과 식민지 방향

2026-10-13. 여러 행성에 식민지를 만들고 각 거점에서 발전하는 사용자 제안을 반영한다. 현재 다중 행성·식민지·수송은 구현되지 않았다. 이 문서는 다음 제국 설계에 반영할 제품 방향이며 수치가 확정된 구현 계획은 아니다.

2026-10-14 상위 방향 추가: 시작 본성은 시즌 은하의 무작위 행성에 정착한다. 이후 식민지는 아래 탐사·입지 선택·개척 순환으로 확장한다. 행성별 자산과 제국 공통 기술은 시즌 종료 때 초기화하며 기록·칭호·외형은 보존한다. [시즌·은하 경쟁·랭킹 방향](DELTA_NOVA_SEASONS_AND_RANKINGS_V0.1.md)을 함께 따른다.

같은 날짜의 [통합 콘텐츠 기획](DELTA_NOVA_CONTENT_BALANCE_V0.1.md)은 식민지 운영·파이오니어·최대5거점·현지 화물·시설 특화와 실제 이동 비용을 연결한다. [v0.2 수송 경제](balance/COLONY_ECONOMY_V0.2.md)는148조건에서 현지 성장·창고 수요·실제 화물과 개척/수송 비용을 계산했다. 개척선만으로 초기 화물을 실을 수 없어 수송선을 동행한다. 이는 현재 개척 기능 구현이나 실제 전쟁 수익성 보장을 뜻하지 않는다.

식민지는 자원 생산·입지·수송·전진기지의 서로 다른 선택을 만드는 제국의 일부다. 본성과 똑같은 시설을 계속 반복하는 관리량보다 행성 간 역할 분담과 함대 배치의 재미를 늘린다. 혼자 모든 기본 행위를 할 수 있고 동맹은 정보·수송·증원을 확장한다.

## 행성마다 다른 발전 이유

| 행성 성격 | 투자와 역할 | 감수할 비용과 약점 |
|---|---|---|
| 균형 본성 | 초반 생산·연구·함대 복구의 안정적인 중심 | 특정 자원의 생산 특화는 약함 |
| 고밀도 암석 행성 | 합금 생산과 대형 조선 거점 | 발전·시설 공간과 자원 수입 관리 |
| 결정 풍부 행성 | 센서·방어막·정밀 기술에 필요한 결정 | 선체용 합금과 연료를 수입할 수 있음 |
| 빙결 행성 | 연료 생산과 장거리 항로의 병참 거점 | 환경 대응 기술과 개발 투자 |
| 항로 교차 행성 | 전진기지·정찰·방어 증원·교역 | 생산량보다 위치에 가치가 있고 노출 위험이 큼 |

위 성격은 게임 규칙 제안이다. 특정 실제 천체의 자원이나 환경에 관한 주장과 구별한다. 행성 크기·환경·자원 성향·시설 공간·거리로 장단점을 만들되 모든 항목이 좋은 한 행성을 정답으로 만들지 않는다. 위치는 기술만으로 없어지지 않는 장기 선택이다.

## 식민지 개척 순환

탐사 → 입지와 자원 성향 확인 → 개척 기술 확보 → 개척선과 초기 화물 준비 → 이동 → 개척 → 현지 생산·발전·저장 투자 → 수송·방어망 연결로 진행한다.

첫 식민지는 생존에 필요한 시설부터 시작한다. 본성의 모든 레벨이나 자원을 복사하지 않는다. 개척선은 성공한 착륙 때 거점 설치에 사용되고 초기 자원은 실제 실어 보낸 화물로 지급한다. 개척 대상을 누군가 먼저 차지했다면 실패 원인을 알리고 개척선과 화물은 귀환시키며 이미 사용한 연료는 비용으로 남긴다.

기술과 운영 능력으로 추가 식민지를 해금한다. 첫 플레이 검증은 본성1개와 새 식민지1개, 성격이 다른 후보 행성2개로 입지 선택과 왕복 수송을 확인한다. 이 수량은 최종 상한이 아니다. 개척에 길드 가입이나 특정 역할 참가자의 접속을 요구하지 않는다.

## 행성 자산과 제국 기술

자원·저장 상한·전력·시설·건설 큐·조선 큐·방어시설·주둔 함대는 행성마다 가진다. 합금이 풍부한 식민지의 자원을 본성의 건조 비용으로 바로 쓰지 않는다. 수송으로 조선소가 있는 행성에 실제 도착해야 한다.

연구 해금과 기술 수준은 제국 공통이다. 연구를 시작하는 기지와 비용 출처는 표시하고 첫 구현은 하나의 제국 연구 큐를 사용한다. 식민지를 새로 만들 때 연구를 처음부터 반복하지 않는다. 건설·조선 작업은 각 행성에서 병행되며 발전 시설과 기술의 공통 효과를 구분해 보여준다.

함대는 실제 위치를 갖는다. 현재 행성에 도킹한 전력만 그곳에서 출격하거나 방어한다. 이동·수송·개척·공격·귀환 중인 함선을 다른 행성에서 복제해 사용하지 않는다. 각 비행에는 출발 행성, 목적지, 보낸 재고·화물·연료, 출발·도착 시각을 기록한다.

## 수송과 방어의 전략

수송은 함선 적재·거리·속도·연료를 지불하는 실제 비행이다. 출발 때 화물은 현지에서 빠져 이동 중 화물로 존재하고 도착 때 한 번 이전한다. 출발 전 목적지 여유에서 도착까지 알려진 생산을 뺀 자원 수요를 확인한다. 예상 밖 초과분은 노출된 선박에 남겨 하역 대기하거나 추가 연료로 반송하도록 명령에서 선택한다. 대기 화물은 가용 현지 비축·지원 완료·무적 자산이 아니며 하역 전 해당 함선을 다른 임무에 복제하지 않는다. 시즌 마감 뒤 도착한 화물은 회수 성과로 소급 계산하지 않는다.

산업 식민지에서 합금을 만들고 본성에서 연구·조선하며, 연료 거점으로 원거리 작전을 지탱하거나 항로상의 기지를 전진 배치할 수 있다. 반대로 먼 식민지는 증원과 회수에 시간이 걸린다. 함대를 외출시키면 그 기지의 주둔 방어가 감소한다.

일반적인 습격으로 상대의 행성 소유권을 영구 탈취하는 규칙은 기본 개척에 넣지 않는다. 영토 점령은 성장 보호·전쟁·복구 규칙과 함께 후속으로 검증한다. 생산 특화가 약한 유저의 복구 기회를 없애는 약탈 대상이 되지 않게 한다.

## 늘어난 행성을 관리하는 화면

상단 행성 선택과 자원 HUD는 현재 선택한 행성을 명확히 가리킨다. 행성을 바꾸면 시설·비용·건설/조선 작업·주둔 함대·방어도 함께 바뀐다. 선택 행성 자원과 제국 전체 합계를 같은 수치로 표시하지 않는다. 제국 총합은 비교용이고 현지 비용 지불 가능량과 별도다.

제국 요약에서 모든 행성의 생산·저장 포화·진행 작업·접근 함대·수송 부족을 비교하고 필요한 거점으로 이동한다. 전체 진행 작업에는 출발지와 목적지를 적는다. 중요한 정보는 행성 이름과 함께 보여주어 메뉴를 여러 번 오갈 필요를 줄인다.

반복 수송은 사용자가 거점·선박·화물 우선순위·현지 예비분·다음 투자비·연료 예산·기한·위험 중단 조건을 정한다. 조건을 만족하면 접속 사이에도 예약 정책을 실행하고 부족·적체·위험 때 멈춰 원인을 알린다. 현지 잉여를 비율로 채우면 목적지 결정/연료 적체가 합금 운송도 막힐 수 있어 수요를 확인한다. 매 행성의 생산 수령 클릭을 핵심 플레이로 만들지 않는다.

## 다음 개발에 적용하는 순서

1. 첫 기지 저장부터 계정의 단일 평면 자원 대신 행성 목록·선택 행성·현지 자산·제국 공통 기술을 분리한다. 처음 행성이 하나여도 이후 식민지를 복제된 별도 게임으로 붙이지 않는다.
2. 생산·조선·방어·정찰·공격·귀환의 첫 성계를 연결하고, 그 다음 플레이 범위에 첫 식민지 개척과 행성 간 수송을 포함한다.
3. 여러 행성의 특화와 반복 운영, 전진기지와 동맹 지원으로 확장한다.

완료 검증은 후보 선택 → 개척 비용 지출 → 도착 후 소유권·기지 생성 → 현지 생산·건조 → 본성으로 화물 수송 → 현지 방어까지 이어져야 한다. 재시작·중복 명령·동시 개척·행성 선택 변경이 소유권과 자원·함대를 복제하지 않아야 한다. 연구는 공유되고 자원과 함대 위치는 공유되지 않는 경계를 검사한다.
