# Delta Nova 기지 운영과 단독 진행

기지의 생산과 정비가 다음 편성을 바꾸고, 개인 작전의 회수 성과가 연구와 시설 투자로 이어지는 서버 저장 성장 단계를 만든다. 혼자 하는 사용자는 개인 작전으로 모든 현재 모듈을 해금하고 공동 작전도 역할을 순서대로 수행해 완료할 수 있다. 여러 명은 준비 부담과 역할을 나눠 진행한다.

## 선택한 구조

브라우저에 별도 경제만 추가하면 공동 작전의 함대와 기지 자산이 분리된다. 개인 저장 전체를 즉시 서버로 교체하면 기존 연습 기록을 위험하게 이전해야 한다. 이번 단계는 개발 참가자별 서버 기지와 개인 작전을 추가하고 기존 브라우저 작전은 편성 연습으로 보존한다. 기지 운영과 공동 작전은 같은 참가자·함대·경제를 사용한다. 실제 계정과 인터넷 서비스는 후속 단계다.

## 생산과 투자

- 참가자마다 합금 120, 보급품 80, 시설 forge/reactor 각 레벨1, 정상 함선9척, 기존 `initialState()` 개인 작전 기록으로 시작한다.
- 합금 제조라인은 분당 6×레벨, 보급 합성소는 분당 4×레벨을 생산한다. 완전한 1분 단위, 미만 시간은 보존, 접속 공백 생산은 최대8시간이다. 저장 상한은 합금 300+100×(forge−1), 보급150+50×(reactor−1).
- 생산은 서버 시각으로 계산한다. 화면은 예상 보유량을 보여주고 `생산 수령` 또는 다른 유효 명령에서 기록한다. GET은 저장과 revision을 변경하지 않는다. 가득 찼을 때 흘린 생산을 나중에 소급 적재하지 않는다. 역행 시각은 생산하지 않는다.
- 시설은 최대3레벨. 현재 레벨×합금40/보급10을 소모하고 해당 생산률과 저장 상한을 높인다. 업그레이드 전까지의 생산은 이전 레벨로 계산한다.
- 개인 연구 모듈은 기존 연구 데이터20에 합금40을 더해 해금하고 하나를 활성화한다. 활성 모듈은 개인·공동 출격 모두 적용한다. 모듈 변경은 개인 작전 보고서를 마무리한 뒤 가능하다.

## 출격과 귀환

- 보급 비용은 선택 함선의 지휘 합계이며 개인 지원 사용 시 +2. 편성 지휘12/최대6척 유지. 출격 전에 비용을 보여준다. 공동 기여 출격에도 지휘 합계 보급을 사용한다. 역할 예약은 자원을 소모하지 않는다.
- 개인 작전은 기존 기본 교전→귀환/추가 진입→결과의 규칙을 서버에서 판정한다. 같은 최고 성과 반복은 연구 데이터를 중복 지급하지 않는다. 회수 화물1개당 합금4를 지급하며 저장 상한을 적용한다.
- 귀환/자동 종료 때 실제 HP 손실을 함선별 정비 필요량으로 기록한다. 출격 중 피해는 귀환 전에 정비할 수 없다. 손실 HP10당 합금1(함선별 올림)로 완전 정비한다. 무력화된 함선도 복구할 수 있다. 정비가 필요한 함선은 다시 출격할 수 없고 다른 정상 함선을 선택할 수 있다.
- 진행 중인 개인 교전이 있으면 공동 기여 출격을 할 수 없다. 완료 보고서는 과거 전투 기록이고 귀환 함선은 정비할 수 있다. 전투 실패도 비용·정비를 남기되 보유 함선과 기지는 영구 파괴하지 않는다.
- 공동 역할 성공은 합금10도 지급하고 기존 공헌10을 유지한다. 공동 성공 공헌20은 완료 역할 수와 무관하게 기여한 참가자당 한 번이다. 동일 참가자가 네 역할을 끝내면 공헌60(10×4+20), 네 명이면 각각30이다.
- 참가자당 미완료 예약은 한 개다. 완료 역할은 다음 역할 예약을 막지 않는다. 완료 기여는 계속 보존된다. 역할 선점과 만료·타인 조작·지원 효과 규칙은 유지한다.

## 저장과 인터페이스

공유 상태 schemaVersion2/rulesVersion base-operations-v2로 변경하고 각 GuildPilot에 BaseState를 추가한다. BaseState는 resources, facilities, lastProducedAt, wear, career(GameState v1)를 갖는다. 모든 숫자와 함선 키·개인 작전 기록을 검사한다. 클라이언트는 자원·생산 시각·승패를 전송할 수 없다.

공동 명령에 collect-production, upgrade-facility(facility), repair-fleet(fleetIds), career-action(action:GameAction)을 추가한다. 기존 commandId/revision/operationId와 영수증 트랜잭션을 그대로 사용한다. 같은 명령의 비용·보상은 한 번만 적용한다.

서버 시작 시 유효한 v1 상태와 영수증 응답 상태를 하나의 트랜잭션에서 v2로 이전한다. 기존 소유권·전투·공헌·revision·원 요청을 보존하고 기지 시작 자원은 한 번만 부여한다. 이전 실패나 알 수 없는 버전은 원본을 보존하고 시작 실패로 드러낸다. 브라우저 연습 저장은 이전하거나 덮어쓰지 않는다.

## 화면과 검증

기지 운영 메뉴에 참가자 연결, 자원/생산률/상한, 시설 투자, 함대 정비, 연구, 개인 작전 준비·관제를 제공한다. 기존 작전 화면을 재사용하고 보급 비용/정비 불가 이유를 출격 전에 표시한다. 공동 화면에도 같은 기지 자원과 정비 경로, 순차 단독 진행 설명을 연결한다. 연구·모듈/생산은 지속 성장의 첫 범위이고 조선·지도·PvP는 뒤에 확장한다.

검증은 시간 경계·상한·업그레이드 전후 생산, 비용 거절과 불변성, 귀환 1회 정산과 정비, 단독/협동 완료, 서버 재시작/영수증 중복, v1 상태/영수증 이전 및 실패 롤백, DOM 흐름과 헤드리스 HTTP를 포함한다. 창을 열지 않고 렌더·모션 체감 검증은 남긴다. 사용자의 추천안 진행 위임에 따라 추가 승인 대기 없이 구현한다.
