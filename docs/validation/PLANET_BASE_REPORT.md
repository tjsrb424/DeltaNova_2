# 행성 기지·조선·대시보드 구현 검증

2026-10-14. 첫 행성 경제 마일스톤을 구현하고 헤드리스 검증을 통과했다. 독립 리뷰에서 발견한 중요한 문제 두 가지를 회귀 테스트로 재현하고 수정했다. 최종 개발 브랜치는 main 통합 전 상태다.

## 실행되는 범위

- 본성1개, 행성별 합금·결정·연료·전력·시설·공사·조선·포대·실제 함선 재고와 제국 공통 연구.
- 시설/조선/연구의 비용·시각·완료·80% 취소 환불, 공간/전력/저장/해금 조건과 입력 검증.
- 건조된 고유 함선을 기존 개인/공동 작전에 실제 편성한다. 출격·귀환 원점, 정비와 자원 정산을 같은 장부에서 관리한다.
- v0.5 기반의 행성 장면, 실제 HUD/시설 선택/행동 패널/진행 목록/재고/개인 편성/보고서. 실제 보유 행성만 표시한다.
- 개인 명령 revision은 공동 작전 교체와 분리한다. 미확정 명령의 원 참가자·원 행성·원 ID를 보존하고 다른 화면에서도 참가자 변경을 막는다.
- SQLite v3 정본과 독립 제국 영수증. 기존 v1/v2 자원·정비·기록·영수증을 원자적으로 이전하고 재시작 때 초기 지급을 반복하지 않는다.

## 신선한 검증

| 명령 | 결과 |
|---|---|
| npm test | 17개 파일 / 156개 테스트 통과 |
| npm run build | TypeScript 검사와 Vite 빌드 exit0 |
| npm run verify:build | HTML/JS/CSS/기존 그림/새 행성 장면의 루프백 HTTP 제공 통과 |
| npm run verify:guild | 4명 공동 완료·결합 지원·중복 요청·1명 네 역할 순차 수행 통과 |
| npm run verify:empire | 실제 HTTP/proxy로 생산·건설·산업 연구·조선·새 함선 출격/귀환/정비·공동 기여·재시작·중복 영수증 통과 |
| npm run simulate | 기존 연습 7,350개 편성/지원/항로와 화물 보존 확인 |

서버 시각을 제어하는 임시 SQLite/루프백 API를 사용했다. 실제 사용자 DB를 초기화하거나 창·브라우저·렌더러를 열지 않았다. Node SQLite의 실험 API 경고는 기존 환경의 알려진 경고이며 위 명령은 모두 exit0이다. 시뮬레이션은 기존 연습 전투의 열거이며 새 경제의 최종 밸런스나 사람이 느끼는 재미의 검증이 아니다.

## 경계와 회귀

- 정각/직전 완료·취소, 소수 분 생산률 변화, 저장 포화 폐기,8시간 오프라인 한도, 역행 시각.
- 두 행성의 비용/환불/귀환 원점과 공통 연구 경계, 신규 함선의 실제 개인/공동 출격과 결정론 보고서 검증.
- SQL 영수증 실패와 손상된 이전 기록의 전체 롤백, 고아 영수증이 있는 DB의 자동 초기화 거절.
- 손상된 저장 영수증은 입력400이 아닌 저장503으로 처리해 클라이언트의 미확정 명령을 보존한다.
- 오래된 조회/영수증 덮어쓰기 방지, 탭 저장 차단, 화면 이동, 세션 재연결, 동일 원 명령 재전송.
- 조선 시작 → 대기 → 공동 조회/예약 → 새 함선으로 실제 기여를 중간 개인 명령 없이 수행한다. 공동 조회는 완료를 투영하며 저장 정본을 변경하지 않는다. 과거 중복 영수증 확인 뒤 최신 공동 조회를 다시 수행한다.
- 개인·공동 양방향 화면 이동 중 미확정 명령을 유지하며 다른 화면의 자산 명령 전송과 실행 버튼을 함께 막는다. 원래 화면에서 재전송을 확인하면 실시간으로 제한을 해제한다.
- 기존 브라우저 연습의 저장 충돌·해금·편성·전투·정산을 유지한다. 새 기본 진입은 행성 대시보드이며 연습은 별도 진입한다.

## 구현 중 확정한 판단

1. 전력 부족이어도 발전소 증설은 허용한다. 그렇지 않으면 증설/방어 완성으로 생긴 부족에서 회복할 수 없다. 잘못된 판단일 경우 시작 조건 예외 하나를 다시 조정해야 한다.
2. 8시간 생산 한도는 한 번의 투영 안에서 모든 사건 구간에 공유한다. 확정된 별도 정산은 새 생산 구간이며 그 사이까지 하나의 오프라인 구간으로 묶지 않는다. 조회는 저장 정본을 확정하지 않는다. 잘못되면 접속 공백 생산 시각을 재조정해야 한다.
3. 영속 정본은 v3이고 기존 공동/base API는 계산한 v2 읽기 view로 유지한다. 자산을 이중 저장하지 않으면서 기존 영수증·클라이언트 계약을 보존한다. 비용은 읽기 어댑터의 유지 관리다.
4. 리뷰가 판단을 보류한 실제 화면/모바일/터치/포커스/모션 체감은 별도 QA로 남긴다. 새 GUI 실행 요청이 없었고 헤드리스 검증을 시각 승인으로 해석하지 않는다. 비용은 미발견 배치/입력 문제의 후속 수정 가능성이다.
5. 리뷰가 판단을 보류한 최종 경제 밸런스/재미는 플레이 검증으로 남긴다. 시제품 수치와 전투 열거만으로 체감 결과를 주장할 수 없다. 비용은 후속 수치 재조정이다.
6. 리뷰가 판단을 보류한 비행/NPC 접근/방어전/개척/수송/실제 계정/PvP는 승인된 이번 범위 밖으로 유지한다. 비용은 다음 마일스톤의 별도 구현과 통합이다.

## 독립 리뷰와 후속 보완

전체 7개 구현 커밋을 새 문맥의 독립 리뷰어가 읽기 전용으로 검토했다. Critical은 없었으며 Important 두 가지는 아래 재현과 수정으로 처리했다. 수정 후 전체 156개 테스트, TypeScript/Vite 빌드, 세 HTTP 검증이 통과했다. 두 번째 리뷰는 수행하지 않았고 수정은 실패한 회귀 테스트 → 수정 → 통과 → 전체 회귀 순으로 검증했다.

- 공동 조회가 저장된 9척만 보여 완료된 10번째 함선을 선택할 수 없던 문제: 실제 HTTP 회귀가 9/10 실패한 뒤 서버 시각의 읽기 투영으로 통과했다. 공동 명령 응답도 현재 view를 반환하며 과거 영수증은 보존한다.
- 다른 화면에 미확정 명령이 있어도 새 자산 명령을 보낼 수 있던 문제: 양방향 훅 테스트가 실제 호출 1회/기대 0회로 실패한 뒤 공통 전송 가드로 통과했다. UI 이동 테스트로 실행 버튼 제한·원 요청 화면 안내·확인 후 제한 해제를 검증했다.
- 경미한 후속 보완: 시간 작업의 완료 이벤트에 대한 중복 없는 polite live 알림. 현재 완료 보고서와 목록은 갱신되지만 보조기기에 완료를 자동 안내하지 않는다.

마무리 검증에서도 17개 파일/156개 테스트가 통과했다. 커밋된 작업 파일은 깨끗하며 개발 작업공간을 보존한다. plan 전용 임시 검증기록 폴더 삭제는 절대 경로와 소유 plan을 확인한 뒤에도 자동 승인 검토에서 `blocked by policy`로 차단되어 보존했다. main 병합/공유 push는 통합 방식 선택 뒤 수행한다.
