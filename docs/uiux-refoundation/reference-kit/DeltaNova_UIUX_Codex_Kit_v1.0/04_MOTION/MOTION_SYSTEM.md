# Delta Nova Motion & Microinteraction System

## 모션의 목적

이펙트가 아니라 **인터페이스의 물리감과 인과관계**를 만든다. 클릭했을 때 무슨 일이 있었는지, 어디로 들어갔는지, 무엇이 완료되었는지, 어떤 위험이 발생했는지 전달해야 한다.

## 타이밍 토큰 (초안)

| 레벨 | duration | easing 성격 | 사용 예 | 지켜야 할 점 |
|---|---:|---|---|---|
| `instant` | 0~80ms | linear | 실시간 숫자, 입력 즉시 반응 | 인터랙션에 지연을 주지 않음 |
| `micro` | 100~180ms | ease-out | Press/Hover/Focus | 과장된 확대 금지 |
| `transition` | 200~300ms | ease-in-out | Panel/Tab/Drawer | 위치 이동과 계층감 |
| `feedback` | 350~550ms | ease-out | 완료/자원 변화 | 성공 ACK 뒤에만 |
| `event` | 400~700ms | ease-out | 위협 알림 등장 | 무한 반복 점멸 금지 |
| `ambient` | 20~80s 또는 비활성 | linear | 행성 자전, 오브젝트 부유 | 게임 상태·성능에 종속 |

실제 기기 측정 후 값을 조정한다. 애니메이션이 길수록 좋아진다는 전제 금지.

## 상태 기반 시퀀스

### 패널 열기
1. 사용자 입력 → 클릭 피드백 즉시.
2. 배경 변화는 작게, 패널 `opacity + translateY/translateX` 전환.
3. 내용이 준비되면 포커스 이동 및 제목을 명확히 강조.
4. 닫힐 때 호출 지점으로 돌아감.

### 빌드 완료
1. 실제 서버 완료 이벤트 수신.
2. 진행 상태가 `완료`로 변경.
3. 자원/레벨이 실제 동기화 상태에 따라 갱신.
4. 행성 아트 단계가 실제로 변했을 때만 이에 맞는 환경 모션.

### 적 함대 접근
1. 위협 eventId 수신 → 우측/상단 경보가 400ms 내 시각적으로 드러나기 시작.
2. 이벤트 심각도에 맞는 레이블/색/아이콘 표시.
3. `공격 정보 보기`/`회피 계획`을 유도.
4. 경보 지속 중 과도한 Shake/Flash 금지, 동일 eventId는 업데이트.

## 구현 기술

- 기본 DOM UI는 CSS transition과 기존 프로젝트의 애니메이션 도구로 충분할 수 있다.
- React 환경일 때 필요한 경우 Motion을 고려: https://motion.dev/docs/react , 레이아웃 전환 https://motion.dev/docs/react-layout-animations
- 고급 아트 시퀀스가 실제로 확정될 때만 Rive 등 상태 머신 방식 검토: https://rive.app/docs
- WebGL/Three.js는 중앙 행성에만 우선 집중하고 UI 텍스트는 가능한 DOM에 둔다.
- `transform`과 `opacity` 위주의 모션 사용, 과도한 layout-triggering 속성 변형 방지.
- 블러/스크롤/파티클이 겹치는 모바일 장면은 GPU/배터리 비용을 따로 측정.

## 가시성/절전

- `prefers-reduced-motion: reduce`에서는 지속 회전/이동/장식 모션을 중지하며 이벤트는 색/글/정적 상태로 전달.
- 브라우저 탭이 백그라운드일 때 장식용 프레임 갱신 최소화.
- 성능 저하 시 단계적으로 `particles → postprocessing → realtime orbit detail → ambient motion` 순으로 줄임.
- 공통 저사양 모드는 실기 테스트 후 도입 여부 결정.

## 사용하지 않을 패턴

- 지속적인 1초 이하 네온 맥동.
- 모든 버튼에 진동/사운드를 붙이기.
- 데이터 값 하나가 바뀔 때 패널 전체를 다시 들어오게 하기.
- 3D 행성 뒤에 읽기 어려운 반투명 텍스트 중첩.
- 명령 확정 전 축하 이펙트.
