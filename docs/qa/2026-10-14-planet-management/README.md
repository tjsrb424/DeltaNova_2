# 행성 관리 UX 검증 · 2026-10-14

실제 API·웹 UI를 임시 DB와 무작위 loopback 포트에서 실행하고 Chromium 헤드리스로 검증했다. GUI 창을 만들거나 기존 사용자 저장 데이터·브라우저 프로필을 사용하지 않았다.

## 자동 확인

- `npm test`: 20개 파일, 182개 테스트 통과.
- `npm run build`: TypeScript 검사와 배포 빌드 통과.
- `npm run verify:build`, `verify:guild`, `verify:empire`: 빌드 파일 HTTP, 공동 작전, 생산·연구·건조·개인 작전·정비 검증 통과.
- `npm run verify:dashboard`: 가로 넘침, 현황/상세 전환, 자체 시설 PNG 디코딩, 런타임 오류 0건.
- 건설 실행 버튼의 화면 내 위치·실제 hit-test·높이 44px 이상을 16개 상태에서 확인했다. 공간 부족/설정 확장 상태에서는 스크롤 후 접근을 확인한다.
- 실행 버튼과 별도로, 증설 효과 표의 각 행을 스크롤해서 표시하고 다른 요소에 가리지 않는지 hit-test했다. 버튼만 보이고 효과는 덮이는 회귀를 검출한다.
- 실제 포인터로 기존 건설 취소 → 결정 채굴소 증설 → 대기열 상세 이동을 수행했다. 서버의 건설 대상, 합금40·결정10·연료10 차감, 선택 유지, 작은 창에서 대기열 접힘을 확인했다.
- 실제 측정값과 차감 전후 자원: [checks.json](checks.json).

창 크기: 1672×941, 1280×720, 1100×650, 900×900, 900×650, 720×650, 720×550, 720×540, 390×844, 390×650, 390×540. 1100×650 및 390×650에서 대기열/참가자 설정/둘 다 펼친 상태도 확인했다.

기존 1100×650 화면의 실행 버튼은 y967px에 있어 화면 밖이었다. 회귀 검사 실패를 확인한 뒤 UI를 변경했다. 독립 리뷰에서 발견한 작은 창의 고정 영역 겹침과 540px 높이의 가로 메뉴 문제도 수정했다.

## 사용자 검수 · 대기

1. 개발 서버에 참가자로 연결하고 창을 약 1100×650으로 줄인다. 건설에서 시설을 바꿔 실제 효과·비용·시간·불가 사유를 확인한다.
2. 진행 가능한 시설을 증설하고 선택이 유지되는지 확인한다. 대기열의 작업명을 눌러 상세로 돌아오고 필요하면 취소·반환을 확인한다.
3. 대기열과 참가자 설정을 펼치고 작은 상세 영역에서 효과 표와 실행 영역을 스크롤해 확인한다. 설정을 접으면 기본 배치로 돌아오는지 확인한다.
4. 대시보드 → 건설 → 함대 → 연구 → 개인 작전 → 보고서 → 대시보드를 오가며 전체 현황과 상세의 역할, 메뉴·버튼의 조작감을 검수한다.

자동 검증은 수치·조작·레이아웃 접근성을 확인한다. 최종 시각적 선호와 실제 플레이의 편의성은 사용자 검수를 기다린다.
