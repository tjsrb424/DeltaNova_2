델타노바(DELTA NOVA)의 UI/UX 전면 재정비를 진행하자.

이 작업의 목표는 단순한 색상 변경이나 SF 이펙트 추가가 아니다. 게임의 경제·정찰·약탈·방어·확장·외교 등 전략적 복잡성을 유지하면서, 사용자에게는 정돈되고 직관적인 프리미엄 우주 제국 관제 인터페이스를 제공하는 것이다.

디자인 방향: Minimal Galactic Command.
- Linear/Geist 수준의 정보 구조와 명확한 글자/간격
- 우주 게임다운 행성의 존재감과 깊이감
- 기본 UI는 차분하고, 중요한 사건에서만 강한 연출
- 중앙 행성은 건설/성장에 따라 외형이 변화하는 핵심 오브젝트
- 공격형/방어형/농장형 플레이어가 필요한 기능에 접근 가능
- 적 함대 접근 시 위험 정보와 대응/함대 회피 계획을 명확하게 노출
- PC 웹 우선, 모바일 반응형까지 구조적으로 고려
- 마이크로 인터랙션은 행동/상태 변화를 명확하게 설명해야 함

[이번 실행의 작업 범위: P0~P2]
1. 저장소 구조, 현재 AGENTS.md, UI 라이브러리, 프런트엔드/라우트, 핵심 화면과 데이터/API 경로, Git 상태를 조사한다.
2. 기존 게임 화면을 실제로 실행·확인할 수 있다면 PC/모바일 기준으로 진단하고, 불가능하면 이유를 밝힌다.
3. 정보 과다, 시각적 불일치, 행동 발견성, 접근성, 모션, 성능 측면에서 주요 결함을 심각도 순으로 평가한다.
4. 이 패키지의 바이블을 현재 코드베이스에 맞게 조정한다. 토큰은 제안값이므로 검증 후 조정할 수 있으며 모든 변경 근거를 기록한다.
5. 기존 운영 페이지나 서버 로직을 교체하지 않는 독립된 데모/분리된 UI 구현에서, 행성 메인 화면 3상태(Idle, Incoming Threat, Action Completed)를 실제 조작 가능한 형태로 제작한다.
6. 사용자가 직접 클릭할 수 있는 주요 내비게이션, 경보 상태 진입/해제, 회피 계획 검토, 패널 전환을 구현한다. 시연 데이터와 실제 데이터를 반드시 구분한다.
7. 가능한 자동 테스트(린트·타입체크·빌드·기존 테스트) 및 반응형/접근성/모션 감소 검증을 실행하고 확인된 결과만 보고한다.
8. 스크린샷 또는 확인 가능한 로컬 실행 방법, 변경된 파일, 원복 방법, UI/UX 10점 만점 평가와 상위 개선점 3~5개를 제시한다.

[중요 금지사항]
- 기존 게임의 경제·전투·정찰·함대 이동·연구·건설 시간·BM·네트워크 수식을 승인 없이 수정하지 말 것.
- 기존 데이터를 지우거나 기능을 빼고 겉으로만 깔끔한 UI를 만들지 말 것.
- 사용자 파일을 덮어쓰거나 Git reset/clean/force push를 하지 말 것.
- React, shadcn/ui, Motion, Rive, Three.js 등을 현재 코드 스택 조사 전에 강제 설치하지 말 것.
- 레퍼런스의 브랜드·화면·에셋을 그대로 복제하지 말 것.
- 실제 서버 ACK 없이 명령 성공 처리하지 말 것. 특히 함대 회피는 자동 발진이 아니라 검토→확정→실제 ACK 흐름이어야 한다.
- 독립 데모의 숫자·타이머는 DEMO임을 표시하며 실제 경제 공식으로 사용하지 말 것.
