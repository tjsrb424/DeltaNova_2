# DeltaNova 디자인·UI/UX 직접 검수 — 2026-10-14

## 판정

Codex의 주 작업자가 실제 렌더링된 화면을 직접 보고 정보 위계·가독성·조작 흐름을 검수했다. 현재 행성 운영 기능의 사용성은 통과다. 메인 운영보드와 건설 상세는 실제 상태를 비교하고 다음 행동을 결정하기에 적합하다. 전체 게임의 최종 미술 완성도와 모든 화면의 디자인 통일까지 완료됐다는 판정은 아니다.

검수는 화면을 띄우지 않는 Chromium의 실제 렌더링, 마우스·키보드 입력, 격리된 실제 API/SQLite를 사용했다. 기존 실행 중인 사용자 서버 데이터는 검증에 사용하거나 변경하지 않았다. 출격·귀환·정비도 버튼 조작과 서버 상태를 함께 확인했다.

## 디자인 판단

| 영역 | 직접 확인한 판단 |
|---|---|
| 메인 | 현재 생산·함대 준비 상태와 진행 중 투자의 완료 효과가 분리되어 있다. 큰 행성 그림보다 수치와 다음 행동이 먼저 보이는 운영보드 방향이 적합하다. |
| 건설 | 시설 목록 → 선택 상태 → 실제 증설 효과 → 비용·시간·불가 사유·실행 순서가 명확하다. 짧은 창에서는 효과 영역을 스크롤해서 공간 변화까지 확인한다. |
| 연구·성장 | 목표 함선의 시설·기술 조건과 남은 개발을 보여주는 지도는 성장 상세에 적합하다. 지도보다 실행이 필요한 상황은 새 바로가기로 선택한 연구 양식에 도달한다. |
| 함대 | 아이콘과 이름의 간격을 좁혀 개별 함선을 식별하기 쉬워졌다. 함선 선택·수량·비용은 실제 본문 높이에 맞춰 배치한다. 함선 그림은 시설 아트보다 완성도가 낮다. |
| 개인 작전 | 추천 편성 → 출격 → 교전 결과 → 귀환 보고서 → 연구 또는 편성 → 정비 흐름을 확인했다. 결과 전환 시 이전 편성의 스크롤 위치를 이어받지 않는다. |
| 동맹·편성 연습 | 이동과 행성 복귀는 정상이다. 기존 어두운 전체 화면과 다른 메뉴 구조를 사용해서 밝은 행성 대시보드와 디자인 연결이 끊긴다. 다음 디자인 통일의 우선 대상이다. |
| 좁은 화면 | 메뉴와 시설 목록의 가로 스크롤로 접근할 수 있다. 메뉴 스크롤의 발견 가능성과 메인 자원 표의 가로 읽기는 더 다듬을 수 있다. 아주 짧은 본문에서 모든 정보를 동시에 표시하지는 않으며 정상 스크롤로 확인한다. |

## 발견하여 수정한 문제

| 문제 | 수정 및 확인 |
|---|---|
| HUD의 전력·시설 공간 수치가 자기 열을 넘어감 | 두 열을 내용에 맞춰 확보했다. 4가지 기본 해상도에서 수치 경계 검증 통과. |
| 함대 아이콘과 이름이 지나치게 멀리 떨어짐 | 공통 SVG의 자동 여백을 재정의하고 함선 행을 축소했다. 아이콘과 이름 간격 12px. |
| 긴 함대·성장 화면에서 실행 양식 찾기 어려움 | 함선 건조·기술 연구 바로가기를 추가했다. 메인·발전지도·대기열에서 명시적으로 상세를 열면 렌더링 후 해당 양식으로 스크롤·포커스를 이동한다. |
| 비용 영역이 건조 수량을 덮음 | 겹치는 고정 영역 대신 본문 높이에 맞춘 카드와 별도 효과 스크롤을 사용한다. 공간이 줄면 장식 미리보기를 축소·생략하며, 260px 미만의 본문과 540px 이하 창 높이에서는 일반 흐름으로 확인한다. |
| 이미 같은 연구 화면에 있을 때 대기열 상세가 지도에 머묾 | 상세 열기 요청을 일반 드롭다운 변경과 분리했다. 같은 행성·같은 대상의 반복 클릭도 상세로 이동하며 드롭다운 조작은 포커스를 빼앗지 않는다. |
| 출격 후 이전 스크롤 위치 때문에 교전 제목이 잘림 | 작전 ID·단계가 바뀔 때 새 화면을 스크롤·포커스한다. 귀환은 작전 보고서에 초점을 맞춘다. 상태 재조회만으로 포커스를 다시 이동하지 않는다. |
| 보고서의 ‘기지 연구로 이동’이 편성만 표시함 | 작전 종료 명령을 보내고 실제 공통 기술 연구 상세로 이동한다. 작전 보상인 연구 데이터는 기존 개인 작전 모듈에서 사용하는 별도 재화다. |

메인 재진입의 스크롤 문제로 보였던 초기 캡처는 캡처 도구의 프로그램 클릭 순서 때문이었다. 실제 마우스 메뉴 전환은 정상이어서 해당 런타임을 수정했다고 기록하지 않는다.

## 검증 근거

- 전체 테스트: 20개 파일, **185개 통과**. 이번 회귀 테스트는 메인 연구 상세, 같은 화면의 대기열 상세와 드롭다운 포커스, 출격·보고서·연구 이동을 확인한다. 새 회귀 테스트가 기존 코드에서 실패하는 것을 확인한 뒤 수정했다.
- TypeScript 검사와 프로덕션 빌드 통과. 빌드된 HTML·JS·CSS·아트의 루프백 HTTP 제공 검증 통과.
- [기본 화면 기록](after/visual-audit.json): 1672×941, 1100×650, 900×650, 390×844에서 메뉴·복귀·바로가기·메인/지도/대기열의 상세 이동 **52개 상태**. HUD 경계, 상세 도착 시 제목·실행 버튼, 입력란의 가림 여부를 확인한다.
- [좁은 양식 기록](after/compact-access.json): 390×650, 1100×600, 900×760, 1100×650에 설정/대기열의 접힘·펼침을 조합한 **16개 상태**. 각 상태에서 함선 선택·수량과 실행 버튼을 정상 스크롤로 접근해 실제 좌표의 hit-test를 확인한다.
- [실제 조작 기록](after/checks.json): 건설 실행 접근 16개, 증설 효과 행 hit-test, 실제 마우스 취소·건설과 자원 차감, 카테고리 전환, 런타임 오류 0건.
- [작전 흐름 기록](after/journey.json): 출격·귀환, 보고서에서 연구로 이동, 실제 정비 필요 여부와 정비 실행, 동맹·연습 진입 및 행성 복귀.
- 독립 코드 리뷰: 최종 포커스·명령 처리·입력 가림 수정에서 병합을 막는 지적 없음. 별도 96개 창 크기/설정 조합도 입력·실행 접근 통과. 미술 판단은 주 작업자가 직접 수행했다.

실제 스크린리더의 발화, 다른 브라우저/기기의 터치 감각, 사용자 개인의 미술 선호까지 검증한 기록은 아니다. 형식적인 접근성 인증을 주장하지 않는다.
