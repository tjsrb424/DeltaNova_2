# 자유 함대 편성 · 아트/모션 검수

2026-10-16 · 독립 데모 · `codex/free-fleet-visuals`

함대 명령은 **빈 편성 → 8함종 직접 수량 선택 → 정확한 조합 검토**로 바꿨다. 새 함선 비트맵 8종, 궤도 격납고 삽화, 선택 피드백과 출항 장면을 적용했다. 운영 UI·서버·게임 수식은 변경하지 않았다.

**현재 함대 화면 내부 평가 9.40/10. 목표9.5는 최종 달성으로 선언하지 않는다.** 이전 메인 행성9.50 평가는 다른 범위의 기록이며, 이번 함대 화면 전체에 자동으로 이어 붙이지 않는다. 점수는 작성자의 판단이고 자동 검사 성공률의 환산이 아니다.

## 검증

- **프로젝트:** 31파일320/320 테스트 통과. 초기0척·직접 조합·입력 노드/초점·행성별 초안·리뷰 무효화·시연 예약·귀환 검사 포함.
- **기존 통합:** 35브라우저 검사, 15상태/화면 조합 통과. 행성3상태·시설·메뉴·은하·동맹·검토/출항·200% 텍스트 회귀 포함.
- **이번 함대 보완:** 14브라우저 검사, 8개 뷰포트. 1920×1080,1440×900,839×1065,390×844,360×800,320×568,844×390,390×390.
- 320/390/가로의200% 텍스트, 검사한 텍스트 대비, 최소44px 수량 조작, 가로 넘침/중복ID, Back, 정확한 조합, 프리셋 부재, 이미지 실패, OS 모션 감소/수동 정지 확인.
- `npm run build`, `npm run verify:build`, `git diff --check` 통과. API/저장 호출·브라우저 런타임 오류0.
- 별도 읽기 전용 리뷰에서 실험실 이미지 넘침과 제거된 disclosure를 가리키던 QA 선택자를 발견해 수정했다. 후속 리뷰에서 모바일 높이 측정의 반복 오류와 Reset 가림 재발이 없음을 확인했다.

브라우저 검증은 Chrome headless다. 실기기 터치·배터리·모바일 GPU·VoiceOver/TalkBack 음성 승인은 수행하지 않았다. [원본 결과와 캡처](../qa/2026-10-16-free-fleet/README.md)를 함께 확인한다.

## 아트 비용과 성능의 실제 관측

원본 PNG 약4MB는 편집 보존용이다. 실행 파일은 아틀라스1280×640/239,316bytes, 격납고1920×640/152,984bytes, 합계392,300bytes(약383KiB). 첫 인코딩630,282bytes에서 약38% 절감했다. 표시용 셀320px는 일반120px 함선 표시의2배 이상이다. 새 라이브러리는 설치하지 않았다. [프롬프트·해시·원본](../art-source/free-fleet-v1/README.md).

기준c251b00의 실제 서빙 소스와 Git 원문이 일치함을 확인한 뒤, 같은1440×900 headless 환경에서 각각3개 콜드 컨텍스트·입력12회씩 측정했다. 최종 표본은 before/after를 교차 실행했다.

| 항목 | 이전 | 최종 | 해석 |
|---|---:|---:|---|
| 수신 아트 body 합계 |470,366bytes |862,666bytes |새 아트392,300bytes 추가 |
| DOMContentLoaded 중앙값 |220.6ms |274.2ms |콜드 로딩 비용 약53.6ms 증가 관측 |
| 입력→doubleRAF 중앙값 |26.8ms |26.6ms |이 짧은 표본의 중앙값은 비슷함 |
| 입력→doubleRAF p95 |29.5ms |38.3ms |꼬리 지연8.8ms 증가 관측 |

공유 PC·무제한 CPU·localhost 표본이다. doubleRAF는 INP/물리 터치 지연이 아니다. 이 결과를 성능 동등/저사양 보장으로 해석하지 않는다. 추가 전송량과 로딩 증가를 비용으로 명시하고, 실기기 프로파일링을 다음 검수 항목으로 남긴다.

## 이렇게 테스트하세요

1. `npm run dev:solo -- --port 5181 --strictPort` 후 `/uiux-demo/index.html#view=command&target=tarsis&intent=attack&context=solo&step=fleet`에 접속한다. 처음0척이며 명령 확인이 비활성인지 본다.
2. 케스트럴·멘더·베일을 각각1척 선택한다. 다른 함종은0으로 유지되고,3척/지휘6/예시 연료17, 이동6분이 표시된다. 명령 확인의3종/3척이 일치하는지 본다.
3. 편성으로 돌아가 수량을 직접 입력하고, 편성 비우기를 누른다. 보유량 초과·함선6척/지휘12 초과 시 검토가 차단되는지 확인한다.
4. 동맹 → 내 함대 합류 준비에서도0척부터 직접 편성한다. 도착 맞추기는 눌렀을 때만 적용된다.
5. 명령 확인 → 출항 시연 → 다음 장면/귀환을 진행한다. 함선·엔진·항로 효과와 예시 상태를 확인하고, 상단 실제 예시 재고가 바뀌지 않는지 본다.
6. 모바일390/360/320px,200% 글자, 모션 감소/화면 설정의 일시정지를 확인한다. 모바일 요약 바로가기와 페이지 맨 아래 초기화 버튼을 모두 눌러 본다.

다음 우선순위는 ① 아트·자유 편성 사용자 검토 ② 실기기에서 목록 길이/음성 접근성/성능 검수다. 데모 승인 후에만 실제 데이터 adapter 설계를 진행한다. 전체 서비스 UI 교체는 진행하지 않는다.
