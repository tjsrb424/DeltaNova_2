# Delta Nova 게임 방향

2026-10-14 최신 사용자 방향: 델타 노바는 시즌제로 진행한다. 은하의 무작위 행성에 정착해 주변을 파악하고 장악하며, 잦은 소규모 전쟁이 길드 형성과 대규모 길드전으로 확장된다. 자원·전투 규모·방어 규모 등 분야별 점수와 랭킹을 제공한다. 시즌 종료 시 행성·자원·함대·연구·영토는 초기화하고 기록·칭호·외형은 유지한다. 상세 방향과 미정 규칙은 [시즌·은하 경쟁·랭킹 방향](DELTA_NOVA_SEASONS_AND_RANKINGS_V0.1.md)을 따른다.

자원을 생산해 시설·연구·함대·방어에 투자하고, 우주에서 상대를 탐색·염탐하여 거리와 전력을 판단한 뒤 공격·방어하는 제국 전략을 한 시즌 안에서 지속한다. 오게임의 성장·정보전 구조를 출발점으로, 우주 문명 게임의 확장과 기지 특화, 현대적인 게임 화면과 마이크로인터랙션을 더한다. 세부 추천안의 진행 위임은 유지한다.

최신 개발 우선순위와 현재 구현의 차이는 [제국 운영 방향 v0.2](DELTA_NOVA_EMPIRE_DIRECTION_V0.2.md)를 따른다. 아래 장기 함종·협동 아이디어가 조선·지도·이동·정찰·기지 방어보다 먼저 구현되어야 한다는 뜻은 아니다.

건설·함대·연구 확장의 수치 후보는 [통합 기획과 밸런스 v0.1](DELTA_NOVA_CONTENT_BALANCE_V0.1.md)을 따른다. 하루1~2회·회당5~10분 관리, 시설24종·방어8종·함선24종·연구36종의 역할·비용·해금·성장 모델을 준비했다. 현재 시제품 가격과 미래 시즌의 표준 비용표는 별도로 유지하고 실제 전투·복수 행성 검증 뒤 확장한다.

다중 행성 개척과 각 행성의 독립 성장은 [식민지 방향](DELTA_NOVA_COLONIES_V0.1.md)을 따른다. 자원·시설·방어·주둔 함대는 현지 자산이고 기술은 제국 공통이다. 처음 기지를 만들 때부터 행성별 모델을 사용해 수송과 전진 배치로 확장한다.

## 핵심 경험

**시즌마다 새로운 행성에서 제국을 성장시키고, 주변 정보와 거리·전력을 판단해 거점을 지키며 영향력을 넓히고, 국지전에서 길드전까지 여러 분야의 성취를 남기는 우주 전략 게임.**

핵심 순환은 생산 → 시설·연구·조선·방어 투자 → 탐색·염탐 → 목표와 편성 선택 → 이동 → 공격·방어 → 귀환·복구·재투자다. 혼자 이 순환을 진행할 수 있고 동맹은 정찰 공유·수송·증원·협공으로 선택을 확장한다. 기존 짧은 작전 테스트는 그 안의 편성과 전투를 검증하는 개발 도구다.

## 전략의 다섯 층

1. **제국 운영:** 생산, 연구, 조선, 저장과 보급 투자로 어떤 역할에 강한 기지를 만들지 선택한다.
2. **정보와 지도:** 탐사로 거점을 찾고, 정찰함과 정보 기술로 상대 자원·함대·방어를 파악한다. 정보의 시각과 신뢰도를 보고 재정찰 여부를 결정한다.
3. **함대 투사:** 거리·함선 속도·연료·수송량·귀환 시간을 보고 목표와 편성을 선택한다. 출항한 함대는 기지를 방어할 수 없다.
4. **방어와 복구:** 주둔 함대·포대·방어막·탐지 시설과 보호 창고로 피해를 관리한다. 방어 센서는 침입 정찰과 접근 함대를 발견하는 별도 투자다.
5. **공동 작전:** 정보 공유·수송·증원·협공으로 각자의 성장과 전력 배치가 서로의 조건을 바꾼다. 역할 과제를 순서대로 수행하는 현재 테스트만으로 협동 전체를 한정하지 않는다.

큰 함대를 갖는 것은 성장의 보상이지만 모든 목표를 같은 대형 전함 편성으로 해결하지 못하게 한다. 작은 함선도 출격 비용, 기동, 표적 대응과 지원 효율로 자리를 갖는다.

## 시즌과 경쟁의 확장

무작위 정착 → 주변 탐색과 성장 → 소규모 분쟁과 영향권 경쟁 → 길드 형성과 협력 → 대규모 길드전과 시즌 기록을 장기 플레이 흐름으로 삼는다. 길드전은 전쟁의 확장 가능성이며 모든 참가자에게 가입과 같은 행동을 강제하는 조건은 아니다. 장악 대상과 영토 규칙은 별도 설계하며 일반 습격으로 상대 본성을 영구 탈취한다고 확정하지 않는다.

운영 추천 기본안은 12주(84일)의 고정 시즌과 종료 뒤 1주 휴식이다. 정해진 종료 시각까지 경쟁하고 선두 길드의 우세로 조기 종료하지 않는다. 개인 종합은 현재 성장 규모, 길드 패권은 전략 거점의 누적 유효 보유 점수로 정하는 안이다. 실제 시작 날짜는 운영 준비 뒤 결정한다.

분야별 랭킹은 자원·전투 규모·방어 규모에 연구·개척·영향권·공격·방어·지원 성과를 더한다. 자원 주 순위는 누적 실제 생산량이고 현재 생산 능력은 별도 순위다. 종합 성장에는 시설·함선·방어·연구의 표준 비용 환산값만 합산해 누적 성과를 중복 반영하지 않는다. 공개 랭킹은 시각을 명시한 1시간 지연 정보로 제공한다. 구체적인 산식과 마감·동률 규칙은 [시즌·랭킹 추천안](DELTA_NOVA_SEASONS_AND_RANKINGS_V0.1.md)을 따른다. 이는 기획 기본안이며 검증된 최종 밸런스나 현재 구현을 뜻하지 않는다.

## 함선 확장

첫 구현의 함종 수는 기술 및 밸런스 검증 범위다. 최종 상한으로 사용하지 않는다. 중기 설계 골격은 다음 15개 역할이며 개별 함명과 수치는 검증 후 결정한다.

| 계열 | 서로 다른 역할 |
|---|---|
| 타격 | 경량 요격, 중장갑 타격, 신속 탈취 |
| 방호 | 집중 공격 호위, 광역 피해 방어, 철수 엄호 |
| 공성 | 방어막 억제, 고정 시설 파괴, 장기 포격 |
| 작전 | 수송과 회수, 구조와 예인, 현장 배치 |
| 지원 | 정찰, 전자전, 보급과 수리 |

새 함선은 역할, 제약, 약점과 사용 상황을 함께 갖는다. 같은 비용에서 기존 함선의 모든 성능을 이기는 상위 호환을 기본 성장 방식으로 삼지 않는다. 개별 레벨 반복 육성보다 함종 및 공용 기술 해금, 작전 모듈 조합을 먼저 검증한다.

## 기지 특화

탐사·전자전 기지는 정보와 접근 경로, 조선·돌파 기지는 전력 투사, 병참·회수 기지는 지속력과 귀환 성과에 강하다. 기본적인 임무 수행은 누구나 가능하고 특화는 효율과 대체 해결법을 제공한다. 특정 직업의 동시 접속이 없으면 길드가 정지하는 구조는 피한다.

시설의 외형과 배치는 기능을 설명해야 한다. 조선소에는 도킹 암과 출항 공간, 탐지 시설에는 펼쳐진 센서 배열, 보급 시설에는 교환 가능한 화물 모듈을 사용한다. 단순한 건물 아이콘 목록을 넘어 자신의 기지가 커지고 역할이 변하는 모습을 보여주는 방향이다.

## 길드 공동 작전

대표 장기 목표는 봉쇄된 도약문 재가동이다. 정찰대는 경로를 열고, 전자전대는 증원을 차단하고, 보급대는 중간 집결지의 복구를 준비하며, 돌파대는 핵심 시설을 제압한다.

모든 참가자가 같은 적 HP를 깎는 방식으로 기여를 축소하지 않는다. 확보한 항로, 차단한 증원, 실제 회복과 구조, 회수한 화물처럼 역할별 결과를 기록한다. 기본 기여 보상과 공동 성공 보상은 분리하고 조건과 분배를 출격 전에 공개한다.

동시 접속을 기본 조건으로 요구하지 않는다. 혼자서는 역할을 순서대로 수행하고, 여러 명은 역할을 나눠 진행한다. 미완료 예약만 참가자당 한 개이며 완료한 기여는 유지한다. 합류 효과에는 역할별 정원과 상한을 두고, 출격 시점의 지원 조건을 고정한다. 개인의 실패가 다른 사람의 확정 보상이나 기지 자산을 회수하지 않는다.

길드가 없는 유저도 소규모 목표와 기본 지원대로 성장할 수 있어야 한다. 길드는 더 복잡한 목표, 새로운 협력과 영토의 의미를 제공한다. 실제 접속 기간, 전쟁 규칙, 보상량과 계정 악용 방지는 서버 단계의 별도 검증 대상이다.

## 위험과 복구

참가자가 선택한 출격 전력, 전선과 미회수 성과에 위험을 둔다. 오프라인 시간 자체를 처벌하거나 큰 유저가 약한 유저의 재기를 막는 구조를 기본으로 삼지 않는다. 보호와 복구는 저장 자원뿐 아니라 함대 투자와 다시 플레이할 수 있는 시간을 함께 본다.

첫 로컬 실험은 보유 함선 영구 손실과 대기 시간을 제거한다. 이는 장기 경제의 확정 규칙이 아니다. 실제 생산·수리·소각 경제는 공격 순수익, 손실 복구 시간, 정찰과 지원의 기회비용을 함께 시뮬레이션하여 정한다.

## 그래픽 언어와 반응

시각 방향은 정밀한 우주 산업 디자인이다. 선체는 밝은 세라믹 외장과 흑연 구조, 열과 추진은 구리빛, 센서와 도킹은 절제된 청록빛을 쓴다. 대형 선체의 실루엣과 기능 모듈을 먼저 읽을 수 있게 한다. 레퍼런스의 함선 모델, 로고, 화면 구성을 복제하지 않는다.

UI의 중심은 행성 개요, 성장하는 기지와 실제 항로가 있는 성계다. 상단은 선택 행성·현지 자원·생산·전력, 중앙은 행성/기지/지도, 우측은 선택한 대상이나 위협의 행동, 하단은 건설·연구·건조·함대 도착을 보여준다. 한글과 큰 형태, 적은 동시 패널, 명확한 선택·부족 사유로 콘솔 게임에 기대하는 읽기 쉬운 품질을 목표로 한다. 사용자 첨부 구성을 다듬은 [행성 대시보드 평상시](../art/planet-dashboard-normal-v0.5.png)와 [공격 접근 상태](../art/planet-dashboard-threat-v0.5.png)는 각각 내부 평가 9.55/10으로 선정한 정적인 레퍼런스이며 런타임 화면이 아니다. [v0.5 평가·프롬프트 기록](../art/PLANET_DASHBOARD_UI_V0.5_REVIEW.md)에 상태별 개선과 한계를 남겼다. 앞선 [다중 행성 기지 시안](../art/empire-colony-ui-v0.4.png)은 시설 상세 방향으로 보존한다. 향후 시안도 [9.5 이상 평가 기준](../art/EMPIRE_COLONY_UI_REVIEW.md)에 따라 검토·개선한다.

선택 120~180ms, 패널 전환 180~260ms, 출격 및 귀환 강조 400~700ms를 최초 기준으로 삼는다. 애니메이션 완료를 기다려야 명령이 처리되는 구조는 피하고 모션 감소 설정을 존중한다.

함선 선택은 편성 슬롯, 남은 지휘 용량과 역할 진단을 즉시 바꾼다. 출격은 예약된 함대가 지도에서 움직이는 피드백을 주고, 지원은 실제 발동 원인을 남기며, 결과는 손실과 성과를 차례로 읽게 한다. 장식 효과는 판단 정보를 가리지 않는다.

## 개발 순서

1. 제국 상태와 실제 보유 함대 재고를 정의하고 생산·시설·연구·조선·방어 건설을 연결한다.
2. 한 성계의 NPC 거점에 실제 이동 시간·연료·정찰 보고서·공격·기지 방어·귀환을 연결해 첫 전체 순환을 완성한다.
3. 위 흐름에 맞춘 기지·성계 화면과 행동 패널·진행 작업·결과 전달을 함께 구현한다. 화면 재설계는 최종 콘텐츠 완성 뒤로 미루지 않는다.
4. 식민지·거점 특화·수송·교역과 동맹의 정보 공유·증원·협공을 확장한다.
5. 실제 계정, 상대 정보 접근 제어, 공개 서버와 PvP의 보호·피해·복구 경제를 검증한다.

현재 구현 상태와 장기 계획은 별도로 보고한다. 2026-10-14 현재 본성1개의 현지 생산·시설·조선·방어 재고·제국 공통 연구와 개인/공동 작전을 같은 로컬 서버 장부에 연결했다. 조선은 실제 보유 함대를 늘리고 포대는 건설·전력·공간·재고까지 제공한다. 성계 거리·이동·정찰 보고서·접근 방어전·개척·수송·실제 계정/PvP·시즌·랭킹·길드전은 후속이다. 브라우저 연습 기록은 별도로 보존한다. 현재 범위는 [README](../../README.md)와 [행성 기지 보고서](../validation/PLANET_BASE_REPORT.md), 이전 경제 단계는 [기지 운영 보고서](../validation/BASE_ECONOMY_REPORT.md)를 따른다.
