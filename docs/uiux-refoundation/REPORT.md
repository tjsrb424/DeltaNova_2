## 1. 판정과 완료 범위

**방향 유지 / 화면 구조 수정 / 기존 서비스 일괄 교체 보류.** P0 진단, P1 바이블 조정, P2 독립 대표 화면 구현과 자동·시각 검증을 완료했다. P3 중 내부 평가 및 수정은 수행했고, 실제 사용자 과제 관찰·모바일 실기 검수·최종 디자인 승인은 남아 있다. **9.5 목표를 달성했다고 판정하지 않는다.**

기존 React 앱, CSS, 경제·전투·함대·정찰·연구·건설 수식, 서버 API, SQLite, 사용자 저장은 변경하지 않았다. 기존 기능은 원본 앱에서 유지된다. 새 화면은 서버·저장을 읽거나 쓰지 않는 독립 DEMO다. 실제 게임 상태 연동과 전체 화면 이관은 승인 이후 범위다.

| 여러 CSS 계층의 색·크기·테두리 중복 | 한 벌의 의미 기반 토큰, 균일한 버튼·리스트·타입 |

| 서버 없는 위협과 완료의 오인 가능성 | DEMO 상시 표기, 고정 예시 ETA, 완료 예시·실제 자산 불변, 미연결 명령 비활성 |

구현 중 캡처/테스트에서 발견한 문제도 수정했다.

1. Canvas의 grid intrinsic 크기로 구체가 잘리는 현상: 명시적 크기·낮은 높이 상한 적용, 6해상도 재검증.
2. 서로 다른 행성의 시설 스냅샷 토글 간섭: 행성별 상태 분리, 실패→통과 회귀 테스트.
3. dialog 경계 Shift+Tab과 재시도 중 DOM 교체로 포커스 유실: Tab 순환, 안정된 호출 위치 탐색/복귀 적용. 독립 리뷰 지적을 재현한 후 수정했다.
4. 초기 텍스처 생성의 약0.8초 연속 메인 스레드 점유:512px 텍스처·8행 단위 비동기 분할·행성별 캐시. 늦은 이전 행성이 현재 선택을 덮어쓰는 경우도 검사한다.
5. Vite의 디렉터리 주소 SPA fallback: `/uiux-demo/index.html`을 명시해 기존 앱과 구별했다.

검사 도구에서도 CSS `zoom:2`가 실제 브라우저의 CSS viewport 변경과 다르다는 점을 확인해 리플로/텍스트 확대를 분리했다. 모바일 context 탐색7초 timeout이 한 차례 발생해 필요 없는 앞 페이지를 닫고 기존 검사와 같은15초 한도를 적용했다. 최종 source 및 dist 검사는 통과했다. 이 기록을 실기 성능의 증명으로 사용하지 않는다.

독립 리뷰: Critical0, Important1(재시도·상세 포커스 복귀) 수정 및 실패→통과 확인. Minor1(대비 검사 범위 한계)은 보고 범위를 정확히 제한해 기록했다. 전 상태·drawer·반투명 합성까지의 자동 대비 확대는 후속 과제다.

## 7. 성능 측정과 한계

같은 PC/헤드리스 Chrome에서 초기 데모를 개선한 비교다. 수치는 단일 실험이며 실기 성능 보증이나 기존 앱 대비 속도 개선으로 해석하지 않는다.

2. 1920×1080/1440×900에서 평시 → 적 함대 접근을 누른다. 경보가 행성 위에 나타나고, 회피 검토 버튼이 즉시 보이는지 확인한다.
3. 회피 검토에서 실제 이동 확정이 비활성인지 확인한다. Escape/닫기로 돌아와도 경보는 유지되어야 한다.
4. 베스퍼를 선택해도 위협 대상은 노바 프라임이어야 한다. 평시로 돌아온 뒤 각 행성의 시설 스냅샷을 변경·복원한다.
5. 평시 → 행동 완료를 누른다. 완료는 **예시**이며 자산 변화가 없어야 한다. 적 접근 중 완료를 누르면 위협이 유지되어야 한다.
6. 390×844/360×800에서 상단 행동·하단 메뉴·더보기·drawer 세로 스크롤을 확인한다. 건설/연구/함대/보고서를 열고 종료 시 호출 버튼으로 포커스가 돌아오는지 확인한다.
7. 빈 작업/연결 오류/다시 표시와 OS 모션 감소를 시험한다. 메뉴와 상태 정보가 사라지지 않아야 한다.
8. 상단 [기존 게임으로 돌아가기](http://127.0.0.1:5173/)를 누른다. 기존 게임은 교체되지 않았고 데모는 기존 저장을 변경하지 않는다.
