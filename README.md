# Delta Nova

함대를 편성하고, 정보를 바탕으로 항로를 정하고, 동료와 역할을 나누어 작전을 완수하는 우주 전략 게임. 오게임을 출발점으로 삼되 델타 노바의 장기 기지 성장·함종별 역할·길드 공동 작전·독자 그래픽을 설계한다.

## 현재 실행 가능한 범위

첫 로컬 작전실 프로토타입이다. 함종 8종/보유 9척 중 최대 6척을 지휘 용량 12 안에서 편성한다. 3개 목표, 정찰·교란·보급 지원, 직행·우회 경로를 조합하고 기본 교전 뒤 귀환 또는 추가 진입을 선택한다. 회수 성과로 기지 모듈 2개를 해금하고 한 개를 활성화한다.

**공동 작전**에서는 같은 로컬 서버에 연결한 개발 참가자들이 정찰·교란·보급·돌파를 나누어 도약문을 복구한다. 각 준비 역할의 전투 성과가 돌파 함대에 함께 적용되고, 공헌과 공동 보상을 서버가 판정·저장한다.

함종 수는 최종 상한이 아니다. 개인 작전의 기본+추가 교전은 위험과 보상을 시험하는 실험이다. 지속 생산 경제, 실제 계정·길드 가입·인터넷 서비스·PvP·결제는 아직 구현하지 않았다. 개인 작전 지원은 로컬 시뮬레이션이고 공동 작전 지원은 다른 참가자가 완료한 역할의 결과다.

## 실행

개발 확인 환경은 Node 24.13.0, npm 11.6.2다. 의존성은 lockfile로 고정한다.

```powershell
cd D:\kim_dev\DeltaNova
npm ci
npm run dev
```

터미널에 표시되는 `http://127.0.0.1:5173`으로 접속한다. 웹 개발 서버와 공동 작전 API(`127.0.0.1:4318`)가 함께 실행되며 두 포트가 사용 중이면 시작 오류로 안내한다. 명령은 브라우저를 자동으로 열지 않는다. 종료는 Ctrl+C. Node의 SQLite 실험 API 경고는 현재 확인 환경에서도 출력된다.

`npm run dev:solo`는 개인 작전만 사용하는 웹 서버다. `npm run preview`는 빌드 파일 확인용이며 공동 작전 API를 실행하지 않는다. 공동 작전은 `npm run dev`를 사용한다.

처음에는 **추천 편성 적용 → 교란 지원 → 작전 출격 → 화물을 가지고 귀환** 순서로 체험할 수 있다. 이후 같은 목표에서 지원·역할·접근 경로를 바꿔 차이를 확인한다. 교전 로그의 각 라운드는 동시 판정이다.

## 공동 작전 체험

공동 작전 메뉴 → 개발 참가자 연결 → 역할 예약 → 역할 추천 편성 → 역할 수행 순서다. 다른 탭에서 다른 참가자를 선택하면 같은 작전 상태를 확인할 수 있다. 참가자는 자유롭게 선택하는 개발용 ID이며 실제 계정 인증이 아니다.

- 정찰 성공은 돌파의 드론 1기를 제거하고, 교란은 첫 라운드 적 사격을 막는다. 보급은 교전 사이 생존 함선마다 최대 20 HP를 복구한다.
- 참가자당 한 역할, 역할당 한 명이다. 예약은 5분 뒤 만료되고 완료 기여는 유지된다. 준비 역할에는 해당 특수 함선의 생존 조건이 있다.
- 돌파는 외곽·핵심 시설을 연속 공략한다. 지원 없이 시도할 수도 있다. 실패 시 동료 기여는 유지하고 돌파 역할을 다시 모집한다.
- 역할 성공 +10, 공동 성공 시 완료 기여자 각각 +20 공헌도다. 개발 반복 검증용 보상이며 개인 연구 데이터와 별도다.
- 연결 실패 시 마지막 확인 상태를 보존한다. 처리 결과가 불확실한 명령은 **같은 명령 재전송**으로 확인한다. 다른 참가자로 바꾸기 전에 결과를 확인해야 한다.
- 공동 상태와 명령 영수증은 `.delta-nova/guild.sqlite`에 저장한다. 서버를 재시작해도 유지되며 개발 세션만 다시 연결한다. 알 수 없는 저장 버전은 자동 초기화하지 않는다.
- 서버는 현재 PC에서만 접근 가능한 루프백에 바인딩한다. 원격 접속과 공개 서비스는 제공하지 않는다.

## 개인 작전 진행과 저장

- 이번 작전에서 무력화된 함선의 화물은 잃지만 보유 함선과 기지는 영구 파괴되지 않는다.
- 임무별 최고 회수 성과의 증가분만 연구 데이터로 지급한다. 같은 결과를 반복하면 추가 지급은 0이다.
- 연구 20으로 모듈을 해금하고 한 번에 하나를 적용한다. 활성 변경은 무료이며 출격 중에는 바꿀 수 없다.
- 같은 브라우저/같은 주소의 로컬 저장을 사용한다. 다른 브라우저·기기·포트와 자동 동기화되지 않는다.
- 잘못되거나 알 수 없는 저장은 자동 덮어쓰지 않는다. `새 연습 시작`을 명시적으로 선택하면 해당 기록을 대체한다.
- 저장 실패는 안내 후 현재 창에서 진행한다. 다른 창의 변경이 감지되면 조작을 잠그고 최신 기록을 불러오도록 안내한다.
- 불러오기가 실패하면 현재 작전을 유지한다. 최초 저장 기록을 읽지 못한 경우에는 기존 데이터를 확인하기 전까지 자동 저장하지 않는다.
- 로컬 저장은 경쟁 서버용 보안 장부가 아니다.

## 검증

```powershell
npm test
npm run build
npm run verify:build
npm run verify:guild
npm run simulate
```

`verify:build`는 임시 루프백 서버에서 빌드 파일과 그림의 HTTP 응답을 확인한 뒤 종료한다. `verify:guild`는 임시 DB/API/Vite proxy로 네 HTTP 세션의 네 역할, 결합 지원, 공헌 30씩 지급과 중복 명령을 검증하고 종료한다. 두 명령 모두 브라우저를 띄우지 않는다. `simulate`는 개인 작전의 합법 편성·지원·경로 7,350개를 열거하고 `docs/validation`의 보고서/CSV를 재생성한다.

검증은 헤드리스로 수행했다. 실제 화면 렌더·모바일 기기·모션 체감·사람이 느끼는 재미는 별도 플레이테스트가 필요하다.

## 다음 개발 순서

1. 장기 기지 성장: 생산·정비·보급·연구 비용과 함종 확장을 연결하고 지속 경제를 검증한다.
2. 협동 전략 확대: 공동 작전 후보·정보·보상 차이와 역할별 편성 선택지를 확장한다.
3. 시각 품질 검증: 화면 렌더와 모션 체감, 결정 이유·결과 전달을 실제 플레이에서 확인한다. 현재 개발의 승인 게이트는 아니다.
