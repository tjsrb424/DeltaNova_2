# 인수인계 및 안전 운영 규칙

## 목적

Codex가 델타노바 UI를 새로 칠하기 전에 **무엇이 문제인지 실제 코드와 화면을 기준으로 진단**하고, 정돈된 화면 구성·모션·기능 접근성을 일관된 디자인 시스템으로 구현하도록 지시한다.

## 범위

### 이번 설계 범위
- 웹 우선 정보구조, 메인 행성 HUD, 위협 상태, 공통 컴포넌트, 상태별 피드백, 반응형 레이아웃.
- 시맨틱 토큰·타이포그래피·기본 모션·접근성·그래픽 레이어의 통합 규칙.
- 향후 빌드/연구/함대/정찰/은하/외교/랭킹으로 확장 가능한 구조.

### 이번 단계에서 승인 없이 금지
- 자원 생산량·소비량, 전투 수식, 건설·연구 시간, 함대 이동·회피 로직 변경.
- 데이터베이스 마이그레이션, 라이브 세이브 변환, 서버 API 계약 변경.
- 진행 중인 다른 기능을 제거하거나 명칭만 유사한 모조 기능으로 대체.
- 신규 UI 패키지를 무단 전면 도입하거나, 기존 프로젝트의 패키지·프레임워크 전환.
- 레퍼런스 게임의 UI 이미지·상표·에셋·폰트를 그대로 복사.
- 실제 확인되지 않은 숫자, 도착 시간, 성공 확률, 자원 비용을 운영 데이터인 것처럼 표기.
- 사용자 승인 없는 외부 서비스 배포, 유료 서비스 가입, 비밀 키 노출.

## 확인해야 하는 사실 목록

- 사용 중인 프런트엔드 프레임워크/라우터/스타일 시스템과 패키지 버전.
- 기존 디자인 토큰·공통 컴포넌트·다국어 지원 및 한국어 표시 기준.
- 메인 행성 화면 라우트, 행성 상태·자원·함대 경보를 공급하는 실제 데이터 모델.
- 상태별 권한·액션 API, 서버 기반 타이밍인지 클라이언트 기반 타이밍인지.
- 렌더링 방식(Canvas/WebGL/DOM), 메모리/성능 제약, 모바일 지원 범위.
- 현재 QA·빌드·린트·테스트 도구, 현재 화면 스크린샷/접근 권한.
- 루트 및 하위 디렉터리의 기존 AGENTS.md, 임시 작업 내용, 브랜치 변경 상태.

## 충돌 우선순위

1. 사용자 최신 지시 + 실제 비즈니스·보안·네트워크 계약.
2. 현재 저장소의 유효한 AGENTS.md 및 코드/테스트가 확인한 사실.
3. 이 패키지의 게임 UX 요구사항 및 접근성·안전 요구사항.
4. 이 패키지의 시각적 권장 수치(색·간격·모션 등) — 제안값이므로 검증 후 조정 가능.
5. 외부 레퍼런스 스타일 — 절대 픽셀 단위로 복제하지 않음.

## 승인 게이트

- **G0 현황 확보:** 저장소/현재 화면/동작 재현/스크린샷 확인.
- **G1 진단:** 주요 문제 10개 이하로 영향도순 분류, 기존 기능 계약 기록.
- **G2 바이블 및 분리된 대표 UI 시연:** 실제 앱과 분리된 데모 또는 feature flag 경로에서 3상태.
- **G3 사용자 디자인·UX 검토:** 수정 목록 반영, 9.5/10 목표 조건 검증.
- **G4 공통 컴포넌트 이관:** 회귀 테스트 통과한 변경만 통합.
- **G5 개별 페이지 점진 확장:** 빌드/연구/함대/은하/동맹/랭킹 순으로 실제 사용 빈도와 위험에 따라 조정.

G0~G2 완료 전에는 메인 화면 전면 교체 금지. G3 승인 전에 실서비스 페이지 전면 대체 금지.

## 보고 원칙

- **확인한 사실 / 아직 모르는 내용 / 디자인 제안**을 분리한다.
- 추측을 사실처럼 쓰지 않는다. 모르는 게임 규칙은 `확인 필요`와 영향을 받는 UI를 함께 제시.
- 모든 변경에는 파일 목록, 이유, 위험, 테스트 증거, 원복 방법을 기록.
- 프로젝트가 Git이라면 기존 사용자 변경을 보존하고, 강제 reset·clean·push·force-push 금지.

## 이렇게 테스트하세요

1. UI를 수정하기 전 핵심 경제·함대 플로우의 베이스라인을 실행하고 결과를 저장한다.
2. 경보 이벤트가 중첩되거나 사라지는 상황에서 UI만 변하고 게임 명령이 자동 실행되지 않는지 확인한다.
3. 기능 미연결 시 명시적으로 `현재 미연결`을 표기하고 실제 성공 상태를 보여주지 않는지 확인한다.
4. G2 보고서에 스크린샷·동작 녹화 또는 재현 경로, 변경된 파일, 테스트 결과가 포함되는지 확인한다.
