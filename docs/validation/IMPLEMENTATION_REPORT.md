# 첫 작전실 구현 검증

2026-10-13. 로컬 브랜치 `codex/command-center-prototype`에서 개발했다. 외부 공개·원격 푸시는 하지 않았다.

## 구현한 것

- React/TypeScript 작전실: 지휘실, 작전 지도, 함대 편성, 기지 연구.
- 함종 8종/보유 9척, 최대 6척/지휘 12. 공성·호위·수리·회수·정찰·전자전·항모 역할.
- 3개 임무, 4개 지원 상태, 2개 경로. 기본 교전 후 귀환 또는 추가 목표 진입.
- 동시 피해와 안정적인 ID 순서, 지원/모듈 출격 스냅샷, 패배·기한 초과·화물 손실과 재도전.
- 임무 최고 성과 증가분 정산, 모듈 해금·활성화.
- 버전 있는 로컬 저장. 결정적 재실행으로 저장 내 전투·함대·로그·정산 기록을 확인한다. 손상 데이터 자동 덮어쓰기 방지, 저장 실패 안내, 다중 탭 변경 잠금과 명시적 불러오기.
- 독자적인 궤도 기지 그림, 역할별 전술 도식, 선택/누름/포커스 피드백, HP 진입 모션, 반응형과 모션 감소 CSS.

결과 패널은 같은 작전 문맥을 유지하도록 `OperationPanel`의 결과 분기로 구성했다. 별도 파일 분리는 현재 규모에서 필요하지 않다. 전투 판정이나 경제 수식은 UI에서 재구현하지 않는다.

## 실행한 검증

| 명령 | 결과 | 입증 범위 |
|---|---|---|
| `npm test` | 39/39 통과 | 규칙 16, 저장 16, React 실제 DOM 흐름 7 |
| `npm run build` | 성공 | TypeScript 검사와 Vite 프로덕션 번들 |
| `npm run verify:build` | 성공 | 빌드 HTML/JS/CSS/기지 PNG가 루프백 HTTP에서 제공됨, 서버 종료 |
| `npm run simulate` | 7,350개 조건 완료 | 기본 귀환과 추가 진입 비교, 모든 결과의 화물 보존 |

전투·저장·UI 모듈은 먼저 실패하는 테스트를 실행하고 구현했다. 작전 중 메뉴가 동작하는 것처럼 보이는 문제는 실패 테스트로 재현하고 메뉴를 잠그는 방식으로 수정했다. 보상 중복, 손상 저장, 지원 해제 뒤 우회 경로, 저장 실패, 외부 저장 변경도 자동 검사한다.

React 점검: 정적 모듈 직접 import, 무거운 외부 UI/애니메이션 의존성 없음, 저장 초기화 지연 실행, 함수형 상태 전이, 이벤트 리스너 해제, 버전 저장, 선택 버튼의 `aria-pressed`, 포커스 표시와 모션 감소를 적용했다.

## 밸런스 관찰

각 임무 2,450개 조건. 초기 수송선 설정은 기본 승리 23개이고 추가 진입 이익이 한 건도 없었다. 수송선 HP 90→60, 교전 기한 4→5라운드로 조정했다. 이후 기본 승리 1,222개, 추가 진입 이익 267개/손해 714개다.

다른 두 임무에서도 추가 진입의 이익과 손해가 모두 존재한다. 자세한 값과 공통 최적 조합 검사는 [열거 보고서](BALANCE_REPORT.md), 전체 결과는 [CSV](balance.csv)에 있다. 이 비율은 합법 조합 열거 결과이며 유저 승률이나 재미의 증거가 아니다.

## 진행 중 판단한 사항

1. 사용자가 추천안 진행을 위임했으므로 세부 설계/실행 방식을 재승인받지 않고 진행했다. 잘못 해석했다면 로컬 프로토타입을 재작업하는 비용이 있다.
2. 사용자가 지정한 새 전용 폴더의 기능 브랜치에서 진행했다. 별도 체크아웃은 만들지 않았다. 이후 동시 작업이 늘어나면 작업 폴더를 분리해야 한다.
3. 고정 3구간/5함종 초안을 확장 가능한 8함종 실험으로 대체했다. 장기 비전은 지속 제국과 길드 공동 작전이다. 세부 재미는 밸런스/화면 반복 개선 비용이 남는다.
4. 호스트 Node 24.13에 맞춰 jsdom을 26.1.0으로 고정했다. jsdom 30의 Node 요구 조건을 충족하지 않았기 때문이다. 새로운 DOM 기능을 시험할 때 도구 업그레이드가 필요할 수 있다.
5. 수송선 교전 수치를 열거 결과에 따라 변경했다. 실제 플레이에서 체감 난도가 맞지 않으면 추가 조정이 필요하다.
6. 결과 화면을 OperationPanel에 통합했다. 필요하면 나중에 컴포넌트 분리 비용이 든다.
7. 첫 결과물은 기존 로컬 기능 브랜치에 보존한다. 통합·외부 발행을 요청받지 않았으므로 해당 선택을 요구하며 진행을 멈추지 않는다. 추후 통합은 별도 작업이다.

## 아직 검증하거나 구현하지 않은 것

- 실제 브라우저 렌더, 1440/390/360px에서의 시각 검사, 모션 체감, 모바일 터치 기기, 사람의 재미 평가. CSS와 DOM 검사만으로 이를 승인했다고 주장하지 않는다.
- 실제 길드원과의 네트워크 협동, 서버 권위 판정, 계정, 지속 생산 경제, PvP, 결제, 앱 배포.
- 최종 함선 아트. 기지는 생성 도구로 만든 첫 시안이고 함선은 역할별 전술 도식이다.
- 지원 비용이 없으므로 지원 선택의 장기 경제적 균형은 미검증이다. 초기 모듈 없음 조건의 열거가 전체 성장 밸런스를 보장하지 않는다.
