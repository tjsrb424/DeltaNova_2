# 행성 기지·조선·대시보드 구현 검증

2026-10-14. 첫 행성 경제 마일스톤을 구현하고 헤드리스 검증을 통과했다. 최종 독립 코드 리뷰는 진행 중이다.

## 실행되는 범위

- 본성1개, 행성별 합금·결정·연료·전력·시설·공사·조선·포대·실제 함선 재고와 제국 공통 연구.
- 시설/조선/연구의 비용·시각·완료·80% 취소 환불, 공간/전력/저장/해금 조건과 입력 검증.
- 건조된 고유 함선을 기존 개인/공동 작전에 실제 편성한다. 출격·귀환 원점, 정비와 자원 정산을 같은 장부에서 관리한다.
- v0.5 기반의 행성 장면, 실제 HUD/시설 선택/행동 패널/진행 목록/재고/개인 편성/보고서. 실제 보유 행성만 표시한다.
- 개인 명령 revision은 공동 작전 교체와 분리한다. 미확정 명령의 원 참가자·원 행성·원 ID를 보존하고 다른 화면에서도 참가자 변경을 막는다.
- SQLite v3 정본과 독립 제국 영수증. 기존 v1/v2 자원·정비·기록·영수증을 원자적으로 이전하고 재시작 때 초기 지급을 반복하지 않는다.

## 신선한 검증

| 명령 | 결과 |
|---|---|
| npm test | 17개 파일 / 150개 테스트 통과 |
| npm run build | TypeScript 검사와 Vite 빌드 exit0 |
| npm run verify:build | HTML/JS/CSS/기존 그림/새 행성 장면의 루프백 HTTP 제공 통과 |
| npm run verify:guild | 4명 공동 완료·결합 지원·중복 요청·1명 네 역할 순차 수행 통과 |
| npm run verify:empire | 실제 HTTP/proxy로 생산·건설·산업 연구·조선·새 함선 출격/귀환/정비·공동 기여·재시작·중복 영수증 통과 |
| npm run simulate | 기존 연습 7,350개 편성/지원/항로와 화물 보존 확인 |

서버 시각을 제어하는 임시 SQLite/루프백 API를 사용했다. 실제 사용자 DB를 초기화하거나 창·브라우저·렌더러를 열지 않았다. Node SQLite의 실험 API 경고는 기존 환경의 알려진 경고이며 위 명령은 모두 exit0이다. 시뮬레이션은 기존 연습 전투의 열거이며 새 경제의 최종 밸런스나 사람이 느끼는 재미의 검증이 아니다.

## 경계와 회귀

- 정각/직전 완료·취소, 소수 분 생산률 변화, 저장 포화 폐기,8시간 오프라인 한도, 역행 시각.
- 두 행성의 비용/환불/귀환 원점과 공통 연구 경계, 신규 함선의 실제 개인/공동 출격과 결정론 보고서 검증.
- SQL 영수증 실패와 손상된 이전 기록의 전체 롤백, 고아 영수증이 있는 DB의 자동 초기화 거절.
- 손상된 저장 영수증은 입력400이 아닌 저장503으로 처리해 클라이언트의 미확정 명령을 보존한다.
- 오래된 조회/영수증 덮어쓰기 방지, 탭 저장 차단, 화면 이동, 세션 재연결, 동일 원 명령 재전송.
- 기존 브라우저 연습의 저장 충돌·해금·편성·전투·정산을 유지한다. 새 기본 진입은 행성 대시보드이며 연습은 별도 진입한다.

## 구현 중 확정한 판단

1. 전력 부족이어도 발전소 증설은 허용한다. 그렇지 않으면 증설/방어 완성으로 생긴 부족에서 회복할 수 없다. 잘못된 판단일 경우 시작 조건 예외 하나를 다시 조정해야 한다.
2.8시간 생산 한도는 한 번의 투영 안에서 모든 사건 구간에 공유한다. 확인된 별도 접속/명령은 새 생산 구간이며 그 사이까지 하나의 오프라인 구간으로 묶지 않는다. 잘못되면 접속 공백 생산 시각을 재조정해야 한다.
3. 영속 정본은v3이고 기존 공동/base API는 계산한v2 읽기 view로 유지한다. 자산을 이중 저장하지 않으면서 기존 영수증·클라이언트 계약을 보존한다. 비용은 읽기 어댑터의 유지 관리다.
