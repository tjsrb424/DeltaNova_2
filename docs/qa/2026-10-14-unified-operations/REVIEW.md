# 동맹·편성 연습 디자인·UI/UX 직접 검수

## 판정

**디자인 통일과 핵심 조작 흐름 통과.** Codex의 주 작업자가 실제 화면을 직접 보고 대시보드와의 일관성, 정보 위계, 선택 피드백, 작은 창의 버튼 접근성을 검수했다. 초기 구현에서 부족한 여백·카드 배치·실행 위치·글자 대비를 수정한 뒤 최종 캡처를 다시 확인했다.

흑연색 공통 메뉴와 밝은 본문이 이어져 기존 두 화면으로 이동할 때 다른 게임처럼 보이던 단절이 줄었다. 동맹은 역할·기여·실행의 관계가 명확하고, 편성 연습은 비용 없는 로컬 연습이라는 맥락을 유지하면서 목표·함대·지원·출격을 찾을 수 있다. 현재 개발 기능을 테스트할 수 있는 디자인·사용성이다. 함선 자산과 전투 연출까지 최종 게임 미술 수준으로 완성됐다는 판정은 아니다.

## 직접 확인하고 수정한 항목

| 검수에서 발견한 문제 | 최종 수정 |
|---|---|
| 메뉴 이름·위치·범위가 대시보드와 다름 | 실제 공통 메뉴 컴포넌트로 통일. 동맹·연습에서도 건설·함대·연구·보고서 등 선택한 대시보드 상세로 이동한다. |
| 큰 기지 그림과 배너가 정보·실행을 밀어냄 | 연습의 큰 장식을 제거하고 동맹 배너를 축소. 현재 상태·역할·목표·편성·실행을 먼저 읽는다. |
| 초기 밝은 테마에서도 자동 여백이 본문을 좁힘 | 본문 폭·여백을 작업 영역에 맞춰 재정의하고 화면 공간을 활용한다. |
| 1100px에서 역할 카드가 두 줄로 밀림 | 충분한 폭에서는 네 역할을 한 줄에서 비교하고 더 좁으면 두 열로 표시한다. |
| 모바일 메뉴의 현재 카테고리가 화면 밖에 남음 | 카테고리 변경과 창 크기 변경 시 현재 항목을 표시한다. 키보드 포커스는 옮기지 않는다. |
| 지원 상세 바로가기 후 출격 버튼이 여전히 화면 아래에 있음 | 실제 본문 높이에 맞춘 브리핑. 지원·항로는 내부 스크롤, 목표·준비 상태·출격은 분리된 아래 영역으로 표시하여 가림을 방지한다. |
| 모듈 화면에 동작하지 않는 지원 바로가기가 있음 | 지원 영역이 있는 연습 화면에서만 바로가기를 표시한다. |
| 역할 클릭 후 과거 보고서가 포커스를 가로챔 | 초기 읽기·역할 변경과 새 수행 결과를 구분한다. 새 결과만 자동으로 보고서에 초점을 맞춘다. |
| 저장된 연습 보고서가 동맹 내용을 대신 표시함 | 동맹에서 로컬 작전·저장 알림·이동 잠금을 적용하지 않는다. 기존 연습 보고서는 보존해 돌아가서 확인한다. |
| 밝은 배경에서 함선 슬롯 이름·결과 숫자·교전 기록이 흐림 | 해당 글자 색과 크기를 보강했다. 기여·작전·모듈 결과도 공통 패널·버튼 규칙을 적용했다. |

선택한 역할 상세, 추천 편성, 예약·수행, 실제 개인 작전 이동, 연습 내 목표·함대·지원·항로·출격·귀환·모듈 이동을 확인했다. 아주 작은 본문에서는 정상 스크롤이 필요하며 모든 정보를 한 화면에 동시에 표시하지 않는다.

## 검증 근거

- 전체 테스트 **20개 파일, 191개 통과**. 기본 185개에서 공통 카테고리 이동, 지원 바로가기, 모듈의 잘못된 바로가기, 역할 브리핑 포커스, 과거 보고서의 포커스 가로채기, 저장된 연습과 동맹의 화면 분리를 검증하는 6개 회귀 테스트를 추가했다. 수정 전 실패를 확인했다.
- TypeScript 검사·프로덕션 빌드 통과. 빌드 파일과 아트의 루프백 HTTP 제공 검증 통과.
- [렌더링·동작 기록](after/unified-review.json): **48개 화면 상태**. 기본 창 크기는 1672×941, 1100×650, 900×650, 390×844, 390×650이다. 문서/본문 가로 넘침, 공통 메뉴 구성, 현재 동맹 항목의 노출, 지원 상세의 출격 버튼 가시성·hit-test를 확인했다.
- 실제 마우스로 연습 출격·귀환 **6회**, 지원·직행/우회 선택, 보고서·모듈 이동, 저장 후 새로고침·동맹 진입·연습 복귀를 확인했다. 연습 5회 전후 실제 제국 상태가 동일함을 검증했다.
- 실제 공동 작전 API로 정찰·전자전·보급·돌파 **네 역할 수행**, 공동 목표 완료와 다음 작전 개설을 확인했다. 역할 사이의 손상 함선 정비는 격리된 테스트 DB의 준비 명령으로 처리했다.
- [기존 대시보드 회귀 기록](after/checks.json): 건설 실행 접근 16개, 증설 효과 행 hit-test, 실제 건설·취소와 비용 차감, 카테고리 이동, 런타임 오류 0건.
- 독립 코드 리뷰에서 이동·포커스·저장 보호·미확정 명령·반응형 CSS를 확인했다. 지적된 두 조작 문제와 형식적인 기존 테스트 선택자를 수정했으며 최종 코드에 병합을 막는 지적은 없다. 미술 판정은 주 작업자가 직접 수행했다.

검증은 headless Chromium과 자체 임시 서버·SQLite·브라우저 프로필에서 수행했다. 사용자 실행 서버의 데이터와 연습 저장값은 테스트에 사용하거나 수정하지 않았다. 폰트와 유한한 화면 전환 애니메이션을 기다린 뒤 캡처했다. 실제 스크린리더 발화·다른 기기의 터치 감각·모든 브라우저 검증을 주장하지 않는다.
