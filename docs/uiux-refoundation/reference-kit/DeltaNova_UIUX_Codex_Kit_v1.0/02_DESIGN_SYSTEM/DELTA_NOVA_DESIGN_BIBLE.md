# DELTA NOVA DESIGN BIBLE v1.0

**상태:** 디자인 시스템 1차 후보. 저장소 실사 및 대표 화면 검증 전에는 최종 확정값이 아님.

## 0. 핵심 문장

> **Quiet by default, cinematic by consequence.**  
> 평소에는 조용하고 정확하게, 사건에는 명확하고 압도적으로 반응한다.

이 방향은 '화려한 SF HUD'가 아니라 '게임을 조작하기 편한 제국 관제실'이다. 모션은 세계의 상태를 전하기 위한 수단이며 장식이 아니다.

## 1. 시각적 기본 성격

- 우주 공간의 깊이는 **행성/배경 레이어**에서 표현한다.
- UI 컴포넌트는 불필요한 광원, 투명 카드, 다중 테두리를 억제한다.
- 타이포그래피·정렬·일정한 간격·시각적 위계로 프리미엄 인상을 만든다.
- 위험·완료·일반 강조색은 고정 의미를 가진다. 단순 취향에 따라 색을 바꾸지 않는다.
- 뷰포트가 바뀌어도 중요한 행동과 상태의 관계가 유지된다.

## 2. 컬러 시스템 (제안값)

| Semantic token | Hex | 용도 |
|---|---|---|
| `bg.canvas` | `#080E18` | 전체 배경 |
| `bg.surface` | `#111B2B` | 중요 패널 |
| `bg.elevated` | `#18263A` | 드로어/모달/부유 컴포넌트 |
| `text.primary` | `#E9F0FA` | 텍스트/숫자 |
| `text.secondary` | `#A8B9D0` | 설명 |
| `text.tertiary` | `#8699B3` | 장식이 아닌 부차 정보; 대비 검사 필요 |
| `accent.primary` | `#52C7DF` | 클릭/선택/진행 상태 |
| `state.warning` | `#F2B85C` | 대비/주의 |
| `state.danger` | `#F16B72` | 적 접근/오류/위험 |
| `state.success` | `#74D4AE` | 확정 완료 |
| `border.subtle` | `#29374C` | 얇은 구획 |
| `focus.ring` | `#9AE7F5` | 키보드 포커스 |

- 배경에 3종 이상의 별도 강조색이 동시에 나오지 않도록 한다.
- 위험 경보는 적색만으로 구분하지 않고 아이콘 + 레이블 + 도착 정보도 제공한다.
- 일반 텍스트 대비 WCAG AA의 4.5:1, 큰 텍스트 및 의미 있는 그래픽 요소 3:1을 목표로 검증한다.
- 게임 정보 그래프에는 채도보다 명확한 단위, 범례, 라벨을 우선한다.

## 3. 타이포그래피

- 한글 우선 시스템 폰트: Pretendard(설치되어 있다면) → Noto Sans KR(가능하면) → Apple SD Gothic Neo → Malgun Gothic → system-ui.
- 비라이선스 상태의 외부 폰트 파일을 임의 패키징하거나 다운로드하여 배포하지 않는다.
- 본문 기본 14~16px, 주석 12~13px(중요 정보 주석은 14px 이상), 카드 제목 16~18px, 페이지 타이틀 24~32px.
- 숫자는 `font-variant-numeric: tabular-nums;`로 자릿수 변화에 흔들리지 않도록 한다.
- 서버 현지화/언어 분기를 침범하지 않고, 한국어 레이블의 줄바꿈과 말줄임을 검증한다.
- 모두 대문자인 영어 UI 타이틀을 본문 대신 남발하지 않는다.

## 4. 공간·형태

- 기본 간격 4px grid. 자주 쓰는 간격 4/8/12/16/24/32px.
- 상위 화면 좌우 패딩 PC 24~32px, 모바일 16px 초기값.
- 패널 반경 12~16px, 버튼 반경 10~12px (종류별 통일).
- 콘텐츠 간 divider는 1px 기본, 그림자나 blur는 별도 근거가 있을 때만 사용.
- 패널 겹침/반투명 Blur가 유효한 경우에만 제한적으로 사용. 기본은 불투명 표면.
- 중앙 행성에 복잡한 원형 눈금/레티클/로어 텍스트를 여러 겹 얹지 않는다.

## 5. 화면 위계

1. **위험/명령 오류** (필요할 때만) — 초점과 행동 유도.
2. **현재 행성/다음 의사결정** — 상시 핵심.
3. **자원/건설/연구 진행** — 압축된 상시 정보.
4. **배경 행성 및 공간감** — 존재감 있지만 정보를 가리지 않음.
5. **분석/로그/상세** — 사용자 요청 시 제공.

## 6. 중앙 행성 아트 디렉션

- 기본: 행성 표면, 야간 도시 광원, 약한 대기광, 깊이감 있는 별 배경.
- 성장 반응: 표면 조명 밀도, 궤도 시설, 운송선 레이어, 주변 산업 활동 등으로 **서로 다른 성장 단계**를 보여준다.
- 현재 코드에서 성장 단계와 연결되는 실제 데이터가 무엇인지 **먼저 확인**한다. 임의의 건물 레벨→아트 단계 임계값을 적용하지 않는다.
- 그래픽 레이어를 분리: `background` / `planet` / `surface activity` / `orbit facility` / `foreground cues`.
- 성능 낮을 때: 고해상도 렌더 대신 정적 이미지·낮은 파티클 수·저비용 CSS 전환을 사용.
- 행성 회전/광원은 관찰 가능한 수준이나 **의사결정 텍스트보다 주목도가 낮아야 함**.
- 중요 경보 시 행성을 가리지 않고 해당 행성 주변에 약한 위협 표시 및 컨텍스트 패널 강조.

## 7. 컴포넌트 스타일 원칙

- 같은 목적의 버튼은 동일한 높이/패딩/색/피드백 사용.
- 버튼 종류: `Primary`(한 영역 하나), `Secondary`, `Tertiary`, `Danger`(파괴적/위험 행동의 심각도 분리).
- 스테이터스는 `neutral / positive / warning / danger / unavailable / loading`으로 관리.
- 비활성 버튼에는 이유를 알 수 있도록 설명 또는 힌트 제공.
- 정보 없는 화살표, 기능 없는 아이콘, 과잉 배지 금지.
- 확정 행위와 검토 행위를 섞지 않는다 (`회피 계획 확인` vs `함대 발진`).

## 8. 마이크로 인터랙션

- 의미가 없는 애니메이션은 하지 않는다. 결과가 아닌 단순 강조는 약하게.
- 클릭/터치: 압력 피드백 100~180ms.
- 탭/패널: 구조가 연속적으로 느껴지는 전환 200~300ms.
- 완료: 상태가 안정적으로 바뀌며 350~550ms 이내 피드백.
- 위험: 짧은 진입 400~700ms. 무한 점멸, 반복 shake, 빠른 flash 금지.
- 모든 지속 모션은 `prefers-reduced-motion`과 성능/탭 비활성 상태를 고려.

## 9. 접근성

- 텍스트/상태/버튼이 배경과 충분히 구분되어야 한다.
- 모바일 핵심 터치 대상은 **권장 44px 이상**, WCAG 2.2 타깃 크기 최소 조건과 간격 예외는 별도 검증.
- 장식 레이어는 스크린리더 탐색에서 제외하며 상태 이벤트는 `aria-live` 등으로 전달.
- 키보드 포커스가 명확하고 모달 종료 시 호출 위치 복귀.
- 위험 정보는 아이콘, 텍스트, 시간과 함께 표현한다.
- 모션 감소 모드에서 기능의 의미가 사라져서는 안 된다.

## 10. AI UI 안티패턴 — 금지

- 모든 카드에 형광 블루 글로우.
- 모든 패널에 투명 blur + 테두리 + 그림자 + 복잡한 그라데이션.
- 10px 내외의 작은 텍스트로 정교함을 가장하기.
- 의미 없는 우주좌표/가짜 난수/레이더 수치를 운영 정보처럼 출력.
- 로그인 랜딩 페이지처럼 거대한 카피 문구로 게임 정보를 밀어내기.
- UI에 불필요한 Particle/GPU 효과를 먼저 추가하기.
- 클릭할 수 없는 장식 버튼, 상태 없는 토글, 가짜 성공 피드백.
- 게임 기능을 모른 채 `shadcn/ui`나 `Three.js`를 강제 도입.

## 11. 디자인 변경 거버넌스

- 디자인 토큰/컴포넌트 바깥에서 임의 hex·새로운 radius를 추가할 때 사유 기록.
- 새 화면은 `메인 상태 + 로딩 + 빈 상태 + 오류 + 이벤트 상태 + 모바일` 스크린샷을 제출.
- 변경은 스토리/컴포넌트 단위의 회귀 검증과 함께 진행.
- **사용자 피드백으로 9.5점이 나올 때까지 무한 이펙트 추가 금지** — 9.5는 주관 점수 + 객관적 UX·성능 조건으로 심사.
