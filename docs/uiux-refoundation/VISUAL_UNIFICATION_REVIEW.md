# 전체 데모 그래픽·모션 통일 검수

2026-10-16 · `codex/demo-visual-unification` · 기준 `766b248119495122d38dbe7e0cd67c0187a1edc7`

함대 화면의 재질/공간감을 나머지 독립 데모로 확장했다. **15개 화면의 그래픽 언어와 모션을 통일하고 출항을 실제 편성 그대로의 네온 편대로 변경했다.** 데이터 연동·운영 UI 교체·게임 수식 변경·main 병합은 수행하지 않는다.

행성 관제의 자연 행성·시설 수준별 광원·위협/완료·회전/구름/위성 기능은 보존한다. 동맹은 기존 도약문과 공통 함대 준비를 유지한다. 미연결 외교/랭킹/보고서에는 시각적 틀을 보완하고 가짜 성과/데이터를 추가하지 않는다. 기존 보유량·6척/지휘12·연료/이동 예시·현지/공통 연구 경계는 유지한다.

## 최종 검증

프로젝트32파일326/326, 기존35통합 검사/15상태, 자유 편성14검사/8뷰포트, 신규11검사/120화면 조합/45글자 확대 조합이 통과했다. TypeScript/Vite build·verify:build·diff 검사를 통과했다. 최종 검사한8개 데모 소스와 dist 해시가 일치하며 채택 아트 manifest도 일치한다. 초기 기본5초 제한의 전체 실행 시간 초과는 단독 재실행과 최종 CLI30초 제한으로 확인했고 제품 assertion은 바꾸지 않았다. 실패·재실행 원문은 QA 폴더에 남긴다.

## 그래픽 게이트

시설V1은 경계 침범으로 반려했고 수정V2만 채택했다. 함종V2의 교란/항모 의미 혼동도 수정했다. 새 후보의 내부 시각 평가는 **시설9.60, 연구9.60, 우주9.75, UI 픽토그램9.70, 함종 픽토그램9.65**다. 모두 사용자가 요청한9.5점 초과 기준에 해당한다. 점수는 원본/실제 크기의 주관적 검토이며 자동 AI 노이즈 검출이나 객관적 인증이 아니다.

[후보·프롬프트·수정/반려 이유·해시](../art-source/visual-unification-v1/README.md)와 [실제 화면 및 QA 원문](../qa/2026-10-16-visual-unification/README.md)을 보존한다. 새로운 래스터3개273,694bytes(약267KiB)를 추가했다. 원본 PNG는 실행용이 아니다. 새 라이브러리는 없다.

## 자체 검토와 독립 검토

원본/작은 표시 크기와 화면 캡처를 각각 검토했다. 별도 읽기 전용 리뷰가 대표 함선만 보이는 문제, 도착 위치가 변하지 않는 문제, 작은 화면의 장식 문구 겹침을 지적했다. 모두 수정하고 실제 glyph 검사·위치/겹침 검사를 추가했다. 후속 리뷰에서 검토 범위 내 blocker 없음으로 확인했다. 리뷰는 실기기·성능 측정·최종 사용자 승인을 대신하지 않는다.

## 이전 커밋과 성능 비교

기준766b248의 데모 전체 파일을 Git blob SHA와 대조한 뒤 동일1440×900 headless Chrome에서 화면별 before/after를 교차 실행했다. 각 화면·버전마다3개의 새 컨텍스트(전체24로드), 함대 명령 입력은 각36회다. API 요청/스크립트 오류는0이다. 원문은 [performance.json](../qa/2026-10-16-visual-unification/performance.json), 재현은 `tools/profile-visual-unification.mjs`다.

| 화면 | DCL 중앙값 이전→현재 | load 중앙값 이전→현재 | 아트 resource body 합계 이전→현재 |
|---|---:|---:|---:|
| 건설 |166.6→169.9ms |227.3→274.7ms |470,366→662,510bytes |
| 연구 |155.8→164.9ms |213.5→226.0ms |470,366→721,364bytes |
| 은하 |159.2→169.5ms |246.2→246.9ms |470,366→683,516bytes |
| 함대 명령 |196.7→191.3ms |278.6→260.3ms |862,666→862,666bytes |

건설의 load 중앙값은47.4ms 늘었고 연구/은하도 로딩 비용이 증가했다. 명령 화면 입력 후 doubleRAF 중앙값은24.3→24.7ms, p95는25.4→25.7ms였다. `decodedBodySize`를 합산한 관측값이므로 캐시/중복 resource entry가 포함될 수 있으며 압축 전송량과 다르다. 추가 실행 래스터 파일 자체는273,694bytes다.

공유 PC·localhost·무제한 CPU의 짧은 표본이다. doubleRAF는 INP/물리 터치 지연이 아니며, 명령 화면의 로딩 중앙값 감소를 개선의 증거로 일반화하지 않는다. 현재 비용 증가를 공개하고 실제 휴대폰의 네트워크/GPU/배터리와 사용자의 작업 발견 시간을 남은 검수로 둔다.

## 이렇게 테스트하세요

1. [인수인계](./HANDOFF.md) 맨 위의 최신 브랜치를 받거나 기존5181 프런트엔드에서 `/uiux-demo/index.html?review=unified-v1#view=construction`을 연다. 건설의6시설을 바꿔 아트·비용이 함께 바뀌는지 본다. 연구에서는 첫 화면의 연구소 비교 버튼과 공통/현지 범위를 확인한다.
2. 연구·함대·출격·은하·동맹·보고서·전체 메뉴·방어·회피·외교·랭킹·실험실을 이동한다. 현재 행성/Back/입력 상태가 유지되고 미연결 상태에 실제 성공이 생성되지 않는지 본다.
3. 함대 명령에서 케스트럴2·바스티온1·멘더1을 직접 편성한다. 검토 → 출항 시연 후 네온4척과 아래 편성표가 일치하는지 본다. 다음 장면은 목적지로, 귀환은 반대 방향으로 표시된다. 메뉴를 나갔다 돌아와도 도착 파동은 다시 재생되지 않는다.
4.390/360/320px·가로·200% 글자로 위 흐름을 확인한다. 연구소 비교/수량 조작/명령 검토/페이지 하단 초기화가 하단 메뉴에 가려지지 않는지 본다. 화면 설정의 ‘모든 화면 모션 일시정지’와 OS 모션 감소도 확인한다.
5. 다음 우선순위는 ① 이 데모의 아트/편대/메뉴를 직접 검토 ② 실제 휴대폰에서 터치·스크린리더·성능 검수다. 데이터 연결과 실제 서비스 교체는 이 검토 이후 별도 승인 범위다.
