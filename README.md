# Delta Nova

자원으로 행성 기지와 함대를 성장시키고, 정보를 바탕으로 작전을 판단하며, 혼자 또는 동료와 우주에서 활동하는 전략 게임.

제품 방향은 시즌마다 무작위 행성에 정착해 주변을 탐색하고, 국지전에서 길드전까지 경쟁을 확장하며 자원·전투 규모·방어 규모 등 분야별 랭킹을 남기는 것이다. 시즌 종료 시 경쟁 자산은 초기화하고 기록·칭호·외형은 유지한다. [시즌·랭킹 기획](docs/design/DELTA_NOVA_SEASONS_AND_RANKINGS_V0.1.md)에 확정 방향과 세부 추천안을 구분했다. 시즌·무작위 배치·랭킹·길드전은 아직 실행되는 기능이 아니다.

기획 추천 기본안은 **12주 고정 시즌 + 1주 휴식**이다. 자원은 누적 실제 생산량, 성장·함대·방어·연구는 보유 자산의 표준 비용, 전쟁·지원·영향권은 유효 누적 성과로 각각 순위를 정한다. 기간·점수 계수는 후속 플레이·경제 검증에서 조정할 수 있는 설계값이다.

[건설·함대·연구 통합 기획 v0.2](docs/design/DELTA_NOVA_CONTENT_BALANCE_V0.1.md)에 하루1~2회·5~10분 관리와 시설24·방어8·함선24·연구36의 후보를 정리했다. [경제/전투 조정](docs/design/balance/BALANCE_REVIEW_V0.2.md)은 동일 투자18·식민지 수송148·전투3,008·약탈8,064·투자 배율1,728표본을 계산해 초기 저장8,000·케스트럴 공격54·지원 투자 비중·수요 확인 수송을 반영했다. 이는 기획/계산 범위이며 실제 서버의 개척·PvP·이동 구현과 구분한다.

## 현재 플레이

기본 화면은 **행성 대시보드**다. 개발 참가자로 연결하면 본성 노바 프라임의 생산·전력·시설·조선·방어 재고·공통 연구와 실제 보유 함대를 확인한다. 행성 장면과 텍스트/HUD/버튼/선택/진행은 분리해서 구현했다.

생산 자원으로 함선을 건조하고, 새 함선을 기존 개인/공동 작전에 실제 편성한다. 귀환 화물·손상·정비·연구 모듈과 기지 자산은 같은 SQLite 장부에 남는다. 기존 무료 **편성 연습**은 별도 메뉴와 브라우저 저장으로 유지한다.

현재 실제 소유 행성은 본성1개다. 복수 행성의 비용/귀환/연구 경계는 테스트 픽스처로 검증했으며 개척·수송 기능이 실행되는 것은 아니다. 포대는 현지 건설·전력·공간·재고까지 제공한다. 성계 이동·정찰 보고서·NPC 공격 접근과 방어전·실제 계정/PvP는 후속 개발이다.

## 실행

UI/UX 재정비는 별도 브랜치 `codex/demo-visual-unification`의 **독립 데모**에서 검증 중이다. [다른 PC에서 이어가기](docs/uiux-refoundation/HANDOFF.md)에 완료 범위·원본 킷/아트·실행/검사·남은 검증을 정리했다. [최신 명령 성능·행동 우선 배치 검수](docs/uiux-refoundation/COMMAND_PERFORMANCE_ACTIONS_REVIEW.md)와 [검증 원문](docs/qa/2026-10-16-command-performance-actions/README.md)을 함께 확인한다. 전체 서비스 UI 이관은 아직 승인되지 않았다. 데모만 실행하려면 `npm run dev:solo -- --port 5181 --strictPort` 후 `http://127.0.0.1:5181/uiux-demo/index.html?review=command-actions-v3#view=construction`에 직접 접속한다.

개발 확인 환경은 Node24.13.0, npm11.6.2이며 의존성은 lockfile로 고정한다.

```powershell
cd D:\kim_dev\DeltaNova
npm ci
npm run dev
```

웹 `http://127.0.0.1:5173`과 API `127.0.0.1:4318`을 함께 실행한다. 브라우저를 자동으로 열지 않으며 포트가 사용 중이면 시작 오류로 안내한다. 종료는 Ctrl+C다. `dev:solo`와 `preview`는 API를 실행하지 않으므로 기지·공동 진행에는 `npm run dev`가 필요하다. 기능 브랜치에서 실행할 때는 해당 체크아웃을 작업 디렉터리로 사용한다.

첫 흐름: **참가자로 연결 → 조선소에서 케스트럴 건조 → 진행 목록/함대 확인 → 개인 작전에서 추천 편성·지원 선택 → 출격·귀환·정비 → 시설/연구에 재투자**. Node SQLite의 실험 API 경고는 알려진 환경 경고다.

## 행성 경제

- 새 참가자는 합금120·결정80·연료80, 생산/발전/조선소/연구소 각 레벨1, 기존8함종/9척으로 시작한다. 신규 함선은 완료된 조선으로 늘어난다.
- 합금은 분당6×광산 레벨, 결정4×채굴소 레벨, 연료4×합성소 레벨이다. 산업 기술 수준을 기본 생산에 더한다. 저장 상한은 각각300/200/150에서 시설 증설에 따라 증가한다.
- 발전소 공급은60×레벨이다. 생산·조선/연구소·포대가 전력을 요구하며 부족하면 생산률이 낮아진다. 전력은 저장 자원이 아니다. 부족해도 발전소 증설은 허용한다.
- 생산은 완전한 분 단위, 접속 공백 최대8시간이다. 시설/연구 완료 시각 이전과 이후의 생산률을 구분하고 저장 포화 때 버린 생산을 되살리지 않는다.
- 행성별 건설 작업1개와 조선 작업1개, 제국 연구 작업1개를 병행한다. 시설 최대5, 기술 최대3, 시설 공간30이다.
- 일반 시설 증설은 현재 레벨L 기준 합금40L·결정10L·연료10L와60L초다. 조선소/연구소는 합금60L·결정30L·연료10L와90L초다.
- 케스트럴1척은 합금40·결정20·연료10와40초다. 함종별 비용·필요 조선소/기술은 화면에서 확인한다. 수량1..20을 선택할 수 있고 예정량은 가용 함대로 세지 않는다.
- 공통 연구의 다음 수준N은 합금40N·결정30N·연료10N와90N초, 연구소≥N이다. 산업은 생산/일부 조선 해금, 정보/방어는 조선 해금에 적용한다. 추진과 정찰 정보의 후속 효과는 성계 단계다.
- 포대1기는 합금50·결정20·연료5와60초, 공간1·가동 전력2를 요구한다.
- 완료 전 취소는 원 지불 행성에 자원별80%를 내림 반환한다. 반환이 저장 상한을 넘으면 취소를 거절하고 공간 부족을 안내한다. 완료 시각부터는 취소할 수 없다.

수치는 첫 경제 시제품의 값이며 최종 밸런스가 아니다. 연구 수준은 제국 공통이고 자원·시설·함선 위치는 현지 자산이다.

## 개인/공동 작전

기존 임무3개와 함종8종을 사용한다. 해당 임무 한 번은 최대6척/지휘12이며 제국 전체 함대의 상한이 아니다. 신규 건조 함선도 실제 편성·전투·귀환·정비에 사용한다.

개인 출격의 연료는 선택 함선 지휘 합계+지원 사용 시2다. 추가 진입에 재청구하지 않는다. 귀환 화물1개당 합금4, 최고 성과 증가분의 연구 데이터, 함선별 손상을 원 출발 행성에 정산한다. 손실 HP10당 합금1을 함선별 올림으로 완전 정비한다. 기존 HP/화물 모듈은 개인 작전 연구20+합금40으로 해금하고 개인/공동 출격에 적용한다.

동맹 메뉴의 공동 작전은 개발용 역할 보드다. 정찰은 드론 제거, 교란은 첫 라운드 사격 억제, 보급은 교전 사이 회복을 제공하고 돌파는 도약문을 복구한다. 혼자 역할을 순서대로 수행하거나 여러 참가자가 나눠 수행한다. 참가자당 진행 예약1개, 역할당1명, 예약은5분이며 완료 기여는 유지한다. 역할 성공 공헌10+합금10, 공동 성공은 각 기여 참가자 공헌20을 한 번 지급한다. 혼자 네 역할을 끝내면60이다.

개발 참가자 선택은 실제 계정 인증/길드 가입이 아니다. 서버는 현재 PC 루프백에만 바인딩한다.

## 저장과 연결 복구

- `.delta-nova/guild.sqlite`의v3 장부가 자산의 정본이다. 개인 제국 명령과 공동 명령은 별도 영수증을 가지며 개인 revision은 공동 작전 교체와 분리한다.
- 기존v1/v2 자원·시설 수준·정비·개인 진행·모듈·공헌·공동 기록과 영수증을 원자적으로 이전한다. 기존 합금은 유지하고 보급은 같은 양의 연료로 옮긴다. 새 결정80과 초기 신규 시설은 한 번만 지급한다.
- 기존 공동/base API는 계산한v2 view로 호환한다. `base`와 `empire`에 같은 자산을 이중 저장하지 않는다. 구형 신규 기지 명령도 본성을 대상으로 현재 시간/비용 규칙을 사용한다.
- 조회는 서버 시각까지의 생산/작업을 투영하고 다음 명령에서 한 번 확정한다. 서버 재시작·같은 완료 조회·동일 명령 재전송이 함선을 복제하거나 보상을 반복하지 않는다.
- 처리 결과가 불확실하면 **같은 명령 재전송**으로 확인한다. 화면/행성 이동과 탭 저장 차단에서도 원 명령을 유지한다. 세션 만료 시 같은 참가자로 연결한 뒤 재전송한다. 확인 전 다른 참가자로 바꿀 수 없다.
- 알 수 없는/손상된 저장을 자동 초기화하지 않는다. 영수증 검증 실패도 미확정 명령을 보존한다.
- 무료 연습의 로컬 저장은 별도다. 다른 창 변경/읽기 실패/손상 기록의 보호를 유지하며 서버 자산으로 자동 복사하지 않는다.

## 검증

```powershell
npm test
npm run build
npm run verify:build
npm run verify:guild
npm run verify:empire
npm run simulate
```

현재162개 테스트와 빌드·두 HTTP/proxy 순환·정적 자산 제공 검증이 통과했다. 기존7,350개 전투 조건 열거도 유지한다. 독립 코드 리뷰의 중요한 문제 두 가지를 회귀 테스트로 재현하고 수정했다. 시간 작업 완료는 행성명을 포함한 polite live 알림으로 안내한다. 같은 완료는 반복 조회/메뉴 이동 때 다시 알리지 않으며 처음 연결한 과거 기록은 읽지 않는다. 모든 자동 검증은 임시 DB와 헤드리스로 수행하며 브라우저/렌더러를 열지 않는다. 실제 화면·좁은 화면·터치·스크린리더 음성·모션·재미는 사용자가 직접 검수할 단계다. [실제 플레이 검수 순서](docs/validation/DASHBOARD_PLAYTEST_V0.1.md), [행성 기지 검증 보고서](docs/validation/PLANET_BASE_REPORT.md)를 따른다.
