# Delta Nova

함대를 편성하고, 정보를 바탕으로 항로를 정하고, 동료와 역할을 나누어 작전을 완수하는 우주 전략 게임. 오게임을 출발점으로 삼되 델타 노바의 장기 기지 성장·함종별 역할·길드 공동 작전·독자 그래픽을 설계한다.

## 현재 실행 가능한 범위

함종8종/보유9척 중 최대6척을 지휘 용량12 안에서 편성한다. **기지 운영**에서는 참가자별 생산·정비·연구와 개인 작전을 서버에 저장한다. 3개 목표, 정찰·교란·보급 지원, 직행·우회 경로와 기본 교전 뒤 귀환/추가 진입을 조합한다. 기존 지휘실·기지 연구는 비용 없는 브라우저 편성 연습으로 유지한다.

**공동 작전**에서는 혼자 역할을 순서대로 수행하거나 여러 참가자가 나눠 도약문을 복구한다. 각 준비 역할의 전투 성과가 돌파 함대에 함께 적용된다. 기지 운영과 같은 함선·보급·정비·활성 모듈을 사용하고 공헌과 보상을 서버가 판정·저장한다.

함종 수는 최종 상한이 아니다. 기지 경제는 생산·정비·연구의 첫 단계이며 조선과 보유 함선 확장, 실제 계정·길드 가입·인터넷 서비스·PvP·결제는 후속 개발이다. 개인 작전 지원은 기본 지원대이고 공동 지원은 완료한 역할의 결과다.

## 실행

개발 확인 환경은 Node 24.13.0, npm 11.6.2다. 의존성은 lockfile로 고정한다.

```powershell
cd D:\kim_dev\DeltaNova
npm ci
npm run dev
```

터미널에 표시되는 `http://127.0.0.1:5173`으로 접속한다. 웹 개발 서버와 공동 작전 API(`127.0.0.1:4318`)가 함께 실행되며 두 포트가 사용 중이면 시작 오류로 안내한다. 명령은 브라우저를 자동으로 열지 않는다. 종료는 Ctrl+C. Node의 SQLite 실험 API 경고는 현재 확인 환경에서도 출력된다.

`npm run dev:solo`는 브라우저 편성 연습용 웹 서버다. `npm run preview`는 빌드 파일 확인용이며 API를 실행하지 않는다. 기지 운영과 공동 작전은 `npm run dev`를 사용한다.

처음에는 **기지 운영 시작 → 참가자로 연결 → 추천 편성 적용 → 교란 지원 → 개인 작전 출격 → 귀환 → 정비/연구** 순서로 체험할 수 있다. 교전 로그의 각 라운드는 동시 판정이다.

## 기지 운영

- 합금120/보급80, 제조라인/합성소 각 레벨1에서 시작한다. 합금은 분당6×레벨, 보급은 분당4×레벨을 생산하고 저장 상한까지 적재한다. 접속 공백 생산은 최대8시간, 완전한 분 단위다.
- `생산 수령`이나 유효한 명령에서 예상 생산을 확정한다. 화면은 마지막 서버 확인 시각 기준이다. 가득 찼을 때 흘린 생산은 이후 증설해도 되살리지 않는다.
- 시설은 레벨3까지 올릴 수 있다. 비용은 현재 레벨×합금40/보급10이며 생산률과 저장 상한이 증가한다.
- 개인 출격 보급은 함선 지휘 합계+지원 사용 시2다. 추가 진입에는 다시 청구하지 않는다. 귀환 화물1개당 합금4를 받고, 연구 데이터는 기존 임무 최고 성과 증가분만 얻는다.
- 귀환 피해는 함선별 정비 필요량으로 남는다. 손실 HP10당 합금1을 함선별 올림으로 지불해 완전 복구한다. 정비가 필요한 함선은 복구 후 다시 출격한다. 출격 중에는 정비할 수 없다.
- 연구 모듈 해금은 연구20+합금40. 활성 모듈은 개인·공동 출격에 모두 적용한다. 모든 현재 연구는 길드 없이 개인 작전으로 해금할 수 있다.
- 기지 자원·개인 작전·공동 상태는 같은 SQLite 장부에 저장한다. 기존 v1 공동 기록과 영수증은 시작 시 원자적으로 이전하며 기존 공헌과 원 요청을 보존한다. 브라우저 연습 진행은 별도로 유지한다.

## 공동 작전 체험

공동 작전 메뉴 → 개발 참가자 연결 → 역할 예약 → 역할 추천 편성 → 역할 수행 순서다. 다른 탭에서 다른 참가자를 선택하면 같은 작전 상태를 확인할 수 있다. 참가자는 자유롭게 선택하는 개발용 ID이며 실제 계정 인증이 아니다.

- 정찰 성공은 돌파의 드론 1기를 제거하고, 교란은 첫 라운드 적 사격을 막는다. 보급은 교전 사이 생존 함선마다 최대 20 HP를 복구한다.
- 참가자당 미완료 예약 한 개, 역할당 한 명이다. 완료 후 같은 참가자가 다음 역할을 맡을 수 있다. 예약은 5분 뒤 만료되고 완료 기여는 유지된다. 준비 역할에는 해당 특수 함선의 생존 조건이 있다.
- 돌파는 외곽·핵심 시설을 연속 공략한다. 지원 없이 시도할 수도 있다. 실패 시 동료 기여는 유지하고 돌파 역할을 다시 모집한다.
- 역할 성공은 공헌10+합금10, 공동 성공은 기여한 참가자당 공헌20을 한 번 지급한다. 혼자 네 역할을 끝내면60, 네 명이 하나씩 하면 각각30이다. 현재 개발 보상이며 공헌도와 연구 데이터는 별도다.
- 연결 실패 시 마지막 확인 상태를 보존한다. 처리 결과가 불확실한 명령은 **같은 명령 재전송**으로 확인한다. 메뉴 이동 뒤에도 이 명령을 유지하며, 탭 저장을 사용할 수 있으면 새로고침 뒤에도 복구한다. 세션이 만료되면 같은 참가자로 다시 연결한 뒤 원래 명령을 재전송한다. 다른 참가자로 바꾸기 전에 결과를 확인해야 한다.
- 공동 상태와 명령 영수증은 `.delta-nova/guild.sqlite`에 저장한다. 서버를 재시작해도 유지되며 개발 세션만 다시 연결한다. 알 수 없는 저장 버전은 자동 초기화하지 않는다.
- 서버는 현재 PC에서만 접근 가능한 루프백에 바인딩한다. 원격 접속과 공개 서비스는 제공하지 않는다.

## 브라우저 편성 연습 저장

- 이번 작전에서 무력화된 함선의 화물은 잃지만 보유 함선과 기지는 영구 파괴되지 않는다.
- 임무별 최고 회수 성과의 증가분만 연구 데이터로 지급한다. 같은 결과를 반복하면 추가 지급은 0이다.
- 연구 20으로 모듈을 해금하고 한 번에 하나를 적용한다. 활성 변경은 무료이며 출격 중에는 바꿀 수 없다.
- 같은 브라우저/같은 주소의 로컬 저장을 사용한다. 다른 브라우저·기기·포트와 자동 동기화되지 않는다.
- 잘못되거나 알 수 없는 저장은 자동 덮어쓰지 않는다. `새 연습 시작`을 명시적으로 선택하면 해당 기록을 대체한다.
- 저장 실패는 안내 후 현재 창에서 진행한다. 다른 창의 변경이 감지되면 조작을 잠그고 최신 기록을 불러오도록 안내한다.
- 불러오기가 실패하면 현재 작전을 유지한다. 최초 저장 기록을 읽지 못한 경우에는 기존 데이터를 확인하기 전까지 자동 저장하지 않는다.
- 로컬 저장은 경쟁 서버용 보안 장부가 아니다.

## 검증

```powershell
npm test
npm run build
npm run verify:build
npm run verify:guild
npm run simulate
```

`verify:build`는 빌드 파일과 그림의 루프백 HTTP 제공을 확인한다. `verify:guild`는 임시 DB/API/Vite proxy로 네 참가자의 협동 성공·중복 명령과 한 참가자의 정비/보급을 포함한 네 역할 순차 완료를 검증한다. 임시 서버를 종료하고 브라우저를 띄우지 않는다. `simulate`는 비용 없는 연습 전투의 편성·지원·경로7,350개를 열거한다.

검증은 헤드리스로 수행했다. 실제 화면 렌더·모바일 기기·모션 체감·사람이 느끼는 재미는 별도 플레이테스트가 필요하다.

## 다음 개발 순서

1. 조선·함종 확장: 생산 자원으로 새 함선을 확보하고 역할별 기지 특화에 연결한다.
2. 협동 전략 확대: 공동 작전 후보·정보·보상 차이와 역할별 편성 선택지를 확장한다.
3. 시각 품질 검증: 화면 렌더와 모션 체감, 결정 이유·결과 전달을 실제 플레이에서 확인한다. 현재 개발의 승인 게이트는 아니다.
