# Delta Nova 공유 공동 작전

사용자는 직접 테스트를 승인 게이트로 두지 않고 다음 개발을 진행하도록 지시했다. 목적은 정찰·교란·보급·돌파의 기여가 다른 참가자의 작전 조건과 공동 보상에 연결되는 실제 공유 상태를 구현하는 것이다. 추천 세부 설계와 로컬 구현은 위임 범위에서 진행한다.

## 선택한 범위

클라이언트 내 모의 참가자만 늘리는 방법은 실제 동시 명령을 검증하지 못한다. 공개 계정 서버부터 구축하면 핵심 협동보다 운영 범위가 커진다. **로컬 HTTP 서버 + 영속 공동 작전 + 여러 개발 참가자**를 먼저 구현한다. 실제 독립 HTTP 세션이 같은 상태를 사용한다. 자유로운 개발 참가자 선택은 계정 인증이 아니며 UI에 이를 명시한다.

기존 개인 작전·로컬 연구 저장은 유지한다. 공동 작전의 공헌도는 서버의 별도 장부이며 개인 연구 데이터와 합치지 않는다. 시안 아트는 재사용하고 공동 역할·기여·전투 결과를 읽을 수 있는 새 화면을 만든다. 새 창을 열지 않고 헤드리스로 검증한다.

## 규칙

- 개발 참가자 네 명: nova(노바), lyra(리라), orion(오리온), vega(베가). 각자는 기존 9척의 개발용 함대를 사용한다.
- 공동 작전은 도약문 재가동 하나. 네 역할은 recon/jam/supply/breach이며 각 정원 1명, 참가자당 작전 하나에서 역할 최대 1개다. 완료 역할도 해당 참가자의 정원을 차지한다.
- 역할 예약은 서버 시각 기준 5분 동안 유효하다. 소유자는 미완료 예약을 해제할 수 있고, 만료 예약은 다른 참가자가 가져올 수 있다. 완료 기여는 만료되지 않는다.
- 역할 수행은 기존 지휘 12·최대 6척 편성 검사를 거친다. 클라이언트는 함선 인스턴스 ID만 전송한다. HP·승패·보상·공헌도는 서버가 계산한다.
- 정찰: 드론 2기와 교전, 정찰함 포함 및 생존 승리 필요. 항로 1개 확보, 돌파의 기본 적 드론 1기 제외.
- 교란: 드론 1기+포대 1기, 전자전함 포함 및 생존 승리 필요. 교란 창 1개 확보, 돌파 기본 교전 첫 라운드 적 사격 차단.
- 보급: 드론 2기+수송선 1기, 회수함 포함 및 생존 승리 후 화물 3개 실제 적재·회수 필요. 돌파 기본 승리 후 생존 함선마다 HP 최대 20 회복.
- 준비 교전은 지원 없음, 모듈 없음, 최대 6라운드다. 실패 시 보상 없이 재편성 또는 예약 해제가 가능하다.
- 돌파: 기존 relay 임무의 기본/추가 교전을 연속 수행한다. 출격 시 완료 지원과 기여자를 스냅샷으로 고정한다. 정찰·교란·보급 효과는 함께 적용 가능하며 전투를 중복 실행하지 않는다. 기본과 추가 모두 승리해야 공동 목표 성공이다.
- 지원이 없어도 독립 돌파는 가능하다. 동일 접속이나 특정 역할을 필수로 요구하지 않는다. 지원은 전투 조건을 개선한다.
- 실패한 돌파는 준비 기여와 그 보상을 유지하고 돌파 예약을 해제하여 재시도 또는 다른 참가자의 합류가 가능하다. 결과 보고서는 보존한다.
- 준비 성공 및 돌파 성공의 개인 공헌 보상은 각 10. 공동 성공 보상은 완료 기여자 모두에게 각 20. 모든 지급은 역할/작전당 한 번. 피해량이나 재시도 횟수로 보상을 늘리지 않는다.
- 공동 성공 후 누구나 다음 작전을 개설할 수 있다. 공헌 장부는 유지하고 역할은 초기화한다. 이는 개발용 반복 검증이며 장기 경제의 확정 보상 모델이 아니다.

## 서버와 저장

Node 24의 `node:http`, `node:sqlite`를 사용한다. SQLite는 해당 런타임에서 사용 가능함을 실제 확인했으며 실험 API 경고를 문서화한다. 트랜잭션으로 상태, 명령 영수증, 보상을 함께 커밋한다. 파일은 Git 제외 `.delta-nova/guild.sqlite`에 저장한다.

- `GET /api/guild`: 현재 상태와 서버 시각.
- `POST /api/dev/session`: 알려진 pilotId에 대해 임의 bearer 세션 토큰 발급. 토큰은 메모리만, 서버 재시작 뒤 재접속. 클라이언트는 탭별 sessionStorage에 저장하되 저장 불가 시 메모리 사용.
- `POST /api/guild/commands`: 토큰의 참가자가 `{commandId, expectedRevision, operationId, action}` 전송. action은 claim/release/contribute/next-operation이며 contribute에만 fleetIds 포함.
- 동일 참가자·동일 commandId·동일 요청은 이전 영수증을 반환한다. 같은 ID의 다른 요청은 거절한다. 중복 확인을 revision 검사보다 먼저 한다. stale revision/operationId는 409, 타인 역할은 403, 잘못된 입력은 400.
- 트랜잭션 시작→중복 검사→최신 상태 읽기→규칙 판정→상태/영수증 기록→커밋을 동기 구간으로 수행한다. 디스크 실패는 롤백하고 성공으로 응답하지 않는다.
- 저장의 알 수 없는 버전/손상은 자동 초기화하지 않는다. 서버 시작/읽기 오류로 드러내고 원본을 보존한다.
- 서버는 127.0.0.1에 바인딩하고 요청 JSON 크기 16KiB, 정확한 Origin/Host와 알려진 필드를 검사한다. CORS wildcard를 쓰지 않는다. 계정 인증·부정행위 방지·인터넷 서비스로 주장하지 않는다.

## 화면

기존 메뉴에 공동 작전 추가. 상단은 도약문 상태와 참가자 연결, 중앙은 네 역할의 소유자·기여·예약, 아래는 선택 역할 편성 및 실제 수행 버튼, 완료 후 개인·공동 보상과 효과 사용량/함대 결과를 표시한다.

상태를 3초 간격으로 읽고 낮은 revision 응답은 버린다. 명령 진행 중 중복 버튼을 잠근다. 통신 오류는 마지막 확정 상태를 유지하고 같은 명령 ID로 재전송할 수 있게 한다. 409는 최신 상태로 갱신하되 사용자의 명령을 자동 재실행하지 않는다. 세션 만료는 재연결 안내다. 비활성 참가자/서버 불가/저장 거절이 성공처럼 표시되지 않는다.

`npm run dev`가 하나의 Node 프로세스에서 로컬 API와 Vite를 시작하며 브라우저는 열지 않는다. Vite는 /api를 로컬 API로 proxy한다. 순수 개인 작전만 필요한 경우 dev:solo를 제공한다.

## 수용 기준

실제 HTTP 클라이언트 두 개가 역할을 나누고 공유 상태·결과·보상을 관찰한다. 동시 선점은 하나만 성공한다. stale 명령, 타인 변경, 승패 위조, 같은 ID 재전송, 서버 재시작 뒤 중복, 저장 실패와 손상 DB를 검증한다. 개인 작전 45개 기존 테스트는 유지한다. 렌더·모션 체감·장기 경제·실제 유저 계정 운영은 이번 자동 검증의 범위 밖이다.
