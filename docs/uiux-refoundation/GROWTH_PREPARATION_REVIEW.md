# 연구·조선·취소/환급 UI 검수

2026-10-16 · 독립 데모 · 비교 기준 `45abb204aa7f038f20d1671dd9fe78a1836d9685`
[실제 검증 원문과 캡처](../qa/2026-10-16-growth-preparation/README.md) · [다른 PC에서 이어가기](./HANDOFF.md)

사용자가 선택한 성장·원정 흐름의 첫 단계인 건설 → 연구·조선 → 정찰·출격 준비를 설계했다. 이번 범위는 연구 선택·건조 계획·취소 전 환급 확인이다. 전투 보고·복구 전체 순환은 다음 단계다.

## 화면과 행동

- 연구: 산업·추진·정보·방어4종 선택, 현재/다음 수준과 효과, 해금 함선, 지불 행성, 자원3종 비용·계획 후 잔량·시간·선행 조건을 표시한다. 추진 속도/정찰 해상도의 후속 효과를 현재 적용된 보너스로 표시하지 않는다.
- 조선: 기존8함종 선택, 정수1~20척 직접 입력/증감, 정확한 합산 비용·시간, 조선소/연구/자원/전력/현재 작업 조건을 보여준다. 기존 V2함선160px 아트를 재사용한다.
- 함대 현황·보낸 함대·항로·조선소 비교·편성 실험실을 유지한다. 조선 내용이 현황을 밀어내지 않도록 현황 뒤에 두고 상단 조선 바로가기로 접근한다.
- 연구의 선택/계획 검토, 조선의 수량/계획 검토는 효과·비용·긴 설명보다 먼저 있다. 연구소/선행 연구/조선소/보유 함대 출격으로 연결한다.
- 건설·제국 연구·현지 건조 대기열에서 취소·환급 검토를 연다. 연구 비용의 출처는 선택 식민지가 아니라 원 지불 행성 노바 프라임이다.
- 환급은 지불/반환 예상/미반환/현재 보유/반환 후/저장 상한을 자원별로 비교한다. 현재 예시·저장 공간 부족 가정·완료 시각 도달 가정을 전환한다. 완료 후 반환 예상은0이다.

## 실제 규칙과 시연의 경계

운영 `src/empire/content.ts`와 동일한 건조 가격/시간/해금과 기술 이름을 테스트로 대조했다. 연구 비용은 다음 수준N의 합금40N·결정30N·연료10N/90N초다. 취소는 원 지불 행성에 자원별 floor(지불×0.8)를 반환하고, 저장 상한 초과와 완료 시각 이후는 불가라는 기존 규칙을 표시한다.

이 모듈은 운영 게임 엔진을 import하지 않는 **읽기 전용 표시/검토용 예시**다. 연구 수준0/최대3 비교와 건조3척 진행41%는 명시한 검토 스냅샷이다. 상단 시설 스냅샷과 빈 작업 도구로 다른 조건을 확인한다. 현재 보유10척에 건조 예정량을 더하지 않는다.

실제 연구/건조 시작과 취소 확정은 항상 **미연결·비활성**이다. 검토 창을 닫아도 대기열/자원/함대/연구가 바뀌지 않으며 취소 성공·완료·보상이나 새 함선을 생성하지 않는다. 실제 정비 대상/손실HP 정보도 연결하지 않아 비용을 임의로 만들지 않는다. API·DB·Storage·새 자동 완료 타이머는 추가하지 않았다. src/, server/, 게임 산식·함대 모델·아트 바이너리·패키지/lock은 변경하지 않았다.

## 검수 중 수정

1. 연구 상태 비교를 재렌더하면 details가 접혀 키보드 초점이 사라지는 문제를 RED 테스트로 재현했다. 펼침 상태와 컨트롤 초점을 유지한다.
2. 닫기 버튼만 있는 네이티브 모달에서 Tab이 BODY로 빠지는 것을 headless Chromium에서 재현했다. 모달 내부 Tab/Shift+Tab 순환과 Escape/닫기 후 시작 버튼 복원을 검사했다.
3. 환급 조건 변경의 안내를 처음에는 모달 밖 live 영역에 기록했다. 별도 읽기 검토에서 showModal 중 외부 영역이 inert/AX 제외된다는 Important1건을 지적했다. 본문 교체 밖이면서 모달 내부인 영속 polite/atomic live 영역으로 이동하고 열린 AX 트리 포함/실제 문자열 변경을 RED→GREEN으로 검증했다.
4. 페이지 탐색 제한을 UI 조작 제한과 분리했다. 공유 PC에서8초 load timeout이 관측돼 원문을 보존하고 페이지 탐색은60초, 조작은8초로 검사한다. 성능 개선 결과로 해석하지 않는다.

## 최종 검증

- 전체33파일·340테스트, build/verify:build 통과.
- 신규11개 흐름·24개 화면/대비·터치·모달AX 검사 통과.
- 기존 행동7, 모바일/접근성11, 통합35/15레이아웃, 자유 편성14/8레이아웃, 전체15화면11검사/일반120·글자200%45레이아웃 통과.
- 최종dist 검수 소스7개가 현재public과 동일한 SHA256임을 확인했다. 열린 모달 내부 알림의 정확한 DOM/AX 노드와 속성·텍스트를 원문에 남겼다.
- 기존 상세창 검수의 포괄 dialog 선택자를 해당 상세창ID로 한정하고 기존 통합 검사를 다시 통과했다.
